# 第五轮：历史必要性与六条件机制对照

日期：2026-10-04。模型：`deepseek-ai/DeepSeek-V4-Flash`，SiliconFlow OpenAI-compatible SDK，temperature=0，thinking=false，零隐式重试。

## 本轮结论

1. **历史批准值对当前二选一提交有必要作用。** 事前声明的六个反事实配对中，Full 为 12/12，No History 为 5/12；双成员均成功的配对分别为 6/6 和 0/6。
2. **未观察到 CS 的行为优势。** 后续 Full、Full+planner、强摘要 S1、两步强摘要 S2、CS1 和同信息 CS-text 均达到已实现检查点评分 12/12。该结果是天花板，不能证明行为等价性。
3. **当前 CS 未降低端到端 Tokens。** CS1 的执行输入减少 24.4%，计入提取后总 Tokens 却比 Full 高 30.1%。S1 的对应数字为减少 34.7%、总量高 12.1%。
4. **评分存在实质覆盖缺口。** 用户提出的证据、引用、脱敏等保留要求没有独立状态或评分变量。来源遗漏可以与满分共存，12/12 只表示冻结 rubric 的成功，不能称完整用户目标达成。

最有用的下一步是先修补评测覆盖和机制区分能力，再设计更小的状态表示。当前证据不足以支持扩展复杂状态系统、训练模型或扩大同类二选一任务的调用量。

## 2. 历史必要性诊断

原 D 包含十二个原候选 checkpoint 和十二个新反事实成员，各比较 Full / No History。预算停止使原候选层不完整，不报告其完整成功率。以下仅报告 **事前单列且全部完成的 24-cell 配对子层**：

| 条件 | 成功/12 成员 | 双成员全成功/6 配对 | 实际 Tokens |
|---|---:|---:|---:|
| Full Context | 12/12 | 6/6 | 75,964 |
| No History | 5/12 | 0/6 | 48,737 |

同一 pair 的当前输入、接口和 No History 首请求相同，只有早期批准事实不同。两个选择均可执行；错误选择也会得到正常执行回执，且第二次提交不能覆盖首次错误而获得成功。因此正常回执不能充当授权答案的 oracle。No History 的若干正确选择可以来自猜测，不能解释为恢复了历史批准值。

六对是不同业务叙述，但共享“旧事实决定不可覆盖的二选一提交”机制；不是六类认知机制，更不是独立长期任务。temperature=0 下仍有两对相同首请求产生不同响应，不假设 API 是确定性的。详见[事前子层报告](../cycle5_diagnostic_v1_20261004/prespecified_counterfactual_stratum.md)。

## 4. 来源正确性与真实行为

60 份来源审阅中，12 份含 concrete error，10 份含 ambiguity，两类可以重叠。最终表示与中间稿分开统计：

| 条件/范围 | 有具体来源问题/审阅数 | 对应本轮评分失败 |
|---|---:|---:|
| Full+planner 的计划 | 3/12 | 0 |
| S1 最终摘要 | 5/12 | 0 |
| S2 整理稿 | 1/12 | 0 |
| S2 最终摘要 | 2/12 | 0 |
| CS1 最终状态 | 1/12 | 0 |

CS-text 继承 CS1 同一源标注，不制造另一份独立来源样本。Full+planner 仍输入完整历史，计划遗漏不等于部署输入丢失；S2 最终提取重新读取完整历史，因此整理稿错误也不自动等于最终表示错误。

代表案例：

- 两份 archive S1 没有保留 redaction/citations 要求；CS1 在 restore 的一个成员中遗漏保留检查和演练记录的义务。这些是目标内容遗漏，本轮评分未测试这些目标。
- `hd01_b` 的额外计划允许首次提交 outcome unresolved 时重试，而没有先确认未生效。这与 once-only 安全前提冲突。本轮工具都成功返回，危险分支没有触发，不能据 12/12 证明该计划安全。
- `hd06_a` 的计划声称 test/client-switch/old-k8 revocation evidence 已保留在历史中；公开历史没有相应详细内容。实际执行仍正确选择批准对象；这没有验证附带证据要求。

公开接口一直提供当前预算，审阅不因状态没有重复该信息而自动判错；摘要也不因缺图或字段而判错。来源标注由项目助手完成，形式可见，且部分“依赖遗漏”标签实际覆盖目标保留义务。它们不是独立人审 gold，也不是已识别的因果机制。CS 的一个错误与 S1 的五个错误是值得后续复核的描述性线索，不能确认 H2。

全部状态及公开来源见[审阅 JSON](../cycle5_mechanism_v3_sources_20261004/source_review.json)，审阅时机和 hash 见[封存记录](../cycle5_mechanism_v3_sources_20261004/source_review_seal.json)。

## 5. 评测覆盖缺口

六对 fixture 都只维护 ready、prepared、preparation_count、committed、commit_count 及一个业务选择字段。脱敏/引用、无障碍/预订数量、检查/演练记录、credit/service、实际 movement、凭据证据都没有各自可变化和可评分的状态变量。工具集只提供两种同步提交，不提供可能破坏这些要求的行动。

因此本轮真正检验的是：**能否从历史保留批准值，并在当前正确提交一次。** 对这一狭窄能力，摘要和 CS 都成功。但未覆盖剩余用户目标，也没有在途异步 job、目标更新、证据失效、未知提交结果或持续状态演化；六十份来源审阅的 missing_pending_job 均不适用。

这个缺口在行为后审查发现，按[覆盖审计](goal_coverage_audit.json)明确记录。冻结评分和成绩没有追溯修改，没有用新标准重算已产生结果。原十二候选的历史必要性仍未充分证明，也不把本次配对矩阵称为独立泛化验证。

## 6. 下一步优先级

1. **先建立目标—世界—评分对应表。** 每条公开成功标准与约束必须有可观察结果或明确的工具保证。需要保留的内容应能真实丢失或被破坏，并由评分识别。准备正确轨迹和至少一条只违背该要求的反例，离线回放检验评分能区分它们。
2. **构造少量具有不同因果结构的工作流。** 优先测试：请求返回但异步 job 未完成；提交结果未知时重复操作风险；旧证据因版本/目标变化失效；多项剩余义务之间的依赖。分别设计可解路径与 No History/遗漏信息的反例，避免只是更换两个选择的名字。可以允许付费恢复历史信息并计成本，不能只靠禁止恢复制造 CS 优势。
3. **再检验最小状态及长期成本。** 为同一公开 checkpoint 的未来任务范围保留必要信息，将强摘要、精简 CS、同信息编码以及干净语义删除对照先锁定。删除需清理所有字段和候选行动中的同义答案。来源和干预审阅完成后才看行为。先小规模检验机制，再决定是否实施原方案的 B 语义消融和 C 多轮成本曲线。

当前不需要继续增加字段。G/W/F 的价值要由未来任务中的信息必要性和成本证明，而不能由 schema 合法、来源引用存在或一次满分支持。设计修改和新任务另建版本，保留本轮输入和结果。
