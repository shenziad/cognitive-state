## 2. 为什么没有进入第三步

预声明门槛要求：CS 最终有效至少 23/24、成功至少 22/24；Full 成功至少 23/24；**两个条件都不得过早完成或执行禁止/缺证据操作**。另需审阅全部 CS 状态，不能虚构已完成操作或新增硬性用户要求。

### Full Context：执行了已取消目标，并错误宣告完成

`pre03r2_goal_revision_b`，repetition 0：

1. p2 旧目标为 silver。
2. p3 明确替换为 gold，并取消 silver。
3. 模型执行 `apply_silver`；回执确认 selected=silver。
4. 模型仍输出 `finish completed`。评分目标 selected=gold 未满足。

另一重复成功；该反例保留在 23/24 中，不选择性重跑。Full 达到了成功数门槛，但违反零严重错误门槛。这里的 `completion_status_correct=true` 仅指终止标签与预期标签一致，**不证明目标完成**；最终成功还依赖所有目标检查，独立 premature_completed 检查捕获了这个问题。

### CS：一份状态的阶段标签超出了证据

`pre03r2_accepted_pending_a`，repetition 0 的 p3 只确认 accepted、submitted=true、done=false；最终状态却写 `world.operations[0].phase=completed`。同一状态保留 done=false 和 consume 义务，执行器也正确完成了任务。

这是**操作阶段标注缺乏对应完成回执**，并非模型宣称整个异步任务已经完成。提交操作完成与异步任务完成的对象层级仍有歧义，当前提示明确要求 accepted/submitted 不自动升级为 completed。审阅按保守口径不认证“零无依据完成阶段”，也不把成功轨迹当作状态正确的替代证据。

24 份最终状态中：发现上述 1 份阶段问题；未发现新增硬性用户要求；没有无依据重开的问题。逐份判断、来源、状态和公共接口保存在 [语义审阅 JSON](../cycle3_preflight_r2_20261003/semantic_review.json)。这是助手来源审阅，不是独立研究者标注。

自动门槛与语义审阅均未通过，见 [gate.json](../cycle3_preflight_r2_20261003/gate.json)。遵守修订计划，本轮到此停止，不降低门槛、不继续调提示直到过关。

## 3. 成本与结论边界

两版共 **96 个组合、228 次真实响应、349,224 Tokens**，没有未知用量请求。两版分别为 113 次/168,718 Tokens、115 次/180,506 Tokens。统计包含初次提取、修复、失败和执行调用。

修订版成本明细：

| 指标 | Full Context | CS v0.3 |
|---|---:|---:|
| 输入 Tokens | 55,895 | 109,677 |
| 输出 Tokens | 588 | 14,346 |
| 已报告缓存输入 Tokens（包含在输入中） | 10,240 | 4,608 |
| API 响应延迟之和（秒） | 48.43 | 279.19 |
| 平均保留表示大小（UTF-8 bytes） | 1,045.0 | 1,332.8 |

这些历史很短，CS 平均表示反而更大，端到端总 Tokens 约为 Full 的 2.20 倍。本轮**没有节省 Context 或总调用成本的证据**；延迟是记录的响应时长总和，不等于并发吞吐或货币费用。6000 bytes 是表示上限，不是等 Token 预算；共同公共接口也占输入成本。

不能据此声称 CS 优于 Summary：本轮没有调用 Summary。24/24 与 23/24 只差一个组合，且同模板重复并非 24 个独立任务，不支持统计优势或行为等价。尚未用新设计运行连续交接，也不能推断长期状态演化有效。

## 4. 当前仍需解决的具体问题

1. **操作与异步任务的阶段作用域。** 需要明确 phase 描述哪个对象，避免把 submission 的响应成功解释为 job 完成；由公共工具契约提供阶段转换依据。未来修订应增加对应离线反例。
2. **依赖有效不等于依赖完整。** 部分按测量选择的 candidate_action.requires 为空或只引用资源。当前验证器能发现悬空/失效引用，却不能发现遗漏了关键测量依赖。还出现把测量得到的颜色嵌入用户要求、只引用用户来源的混合表达。
3. **任务成功会掩盖冗余或不一致字段。** 一份 pending 状态资源只写在 claim 中、resources 为空；一份旧假设缺少显式失效标记；一份零余额约束措辞过宽。均未造成这次执行失败，但可能影响下一次更新。
4. **门槛设计也需要审查。** 当前规则把 Full 的一次任务能力错误作为整轮停止条件，这是冻结计划的实际含义。本轮遵守；后续应在调用前区分实验设施/输入无效与模型的可测行为失败，明确哪些错误阻止比较、哪些作为结果进入分母，避免事后豁免。
5. **输入封装有多层 JSON 字符串转义。** 四条件共用旧执行器传输层，但不同表示格式的转义开销可能不同。后续应检查更直接的统一消息封装；本轮不改动冻结代码，也不将 Full 失误归因于转义而无实验依据。

下一轮建议先明确阶段作用域与门槛分类、补充对应离线验证，再冻结新版本做小预检；满足新计划后运行已准备的四组比较与四次交接。比较任务此前已查看，应定位为回归测试；独立的未见任务与长历史成本曲线需要另外设计。
