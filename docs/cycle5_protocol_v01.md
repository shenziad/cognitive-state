# 第五轮：历史必要性诊断与最小机制对照 v0.1

日期：2026-10-04。状态：**执行前规范；冻结清单完成后生效，模型尚未调用**。数据、运行器、消息投影、配置、顺序、审阅规则及分析代码已就绪并经离线检查；完整资产写入冻结清单并验证后，才可发送本阶段真实模型请求。本文件不是对第四轮的追溯注册，不修改任何第四轮冻结资产。

## 1. 本阶段为什么这样设计

第四轮完成 96 组预检、56 组回归、32 段连续交接。archive 链的摘要丢失已确认的修复分支，随后实际阻塞；两版 CS 与 Full 保留身份并成功。这只是一条已知开发工作流中的线索。v0.3.1 在连续交接的完整总 Tokens 比 Full 高约 60%，没有达到成本目标；旧 claim 与新的成功状态并存，也说明编码有效不保证更新语义正确。详见[第四轮报告](../results/analysis/research_cycle4_20261004/analysis.md)。

下一阶段先检查任务是否确实需要历史，再比较信息提取、额外推理与呈现方式。本文只安排 **D：历史诊断**和 **A：六条件机制比较**。跨字段语义消融 B、长期成本曲线 C、训练与状态更新重设计不在本次运行范围。原[机制草案](mechanism_and_cost_plan_v01.md)中的建议不自动成为本次冻结内容。

两类数据均为助手在已知项目问题后构造的合成开发数据，不是自然生产任务、独立研究者 gold 或正式 held-out。新反事实版本来自已知业务工作流；改变早期事实不会增加独立工作流数量。

## 2. 数据和事前选择

### 2.1 原候选诊断：12 个单 checkpoint

从已审阅的 12 条工作流固定选择下表中的一段。使用公开事件及离线真实前史回放构造该段初始世界，所有条件从相同快照开始。前史是合成环境中已验证发生的动作/回执，不能称为前段模型已经完成的工作。

| 原候选 | 固定 checkpoint | 当前决策/可恢复性诊断 |
|---|---|---|
| iw01 | h2 | 发布时点修改；当前消息可能已给时点 |
| iw02 | h4 | 完成认证工单；当前交付契约和已完成世界可能使旧诊断不影响选择 |
| iw03 | h4 | 成对结果交付；目录/世界可能使旧对象事实不必由表示保存 |
| iw04 | h4 | 允许资产的发布；当前规则可能已给选择 |
| iw05 | h4 | 发布综述；已完成状态可能由环境保留 |
| iw06 | h4 | 校准放行；可能只有一个可行交付操作 |
| iw07 | h2 | 酒店地点变更；当前更新可能重述选择 |
| iw08 | h3 | 通知渠道；当前要求可能重述 email |
| iw09 | h4 | 生产恢复快照；当前目录可能给出 s8 |
| iw10 | h2 | 更正队列版本；新事件可能足以决定当前拟合 |
| iw11 | h4 | 凭据轮换留档；可能由当前状态和唯一操作决定 |
| iw12 | h4 | 库存报告；可能由当前状态和唯一操作决定 |

这些诊断不能因 Full 与 No History 同样成功而删去。正确对象出现在工具名中、环境保留状态或有可恢复观察，均是任务能力的一部分，也可能限制其对模型历史保存能力的区分。

### 2.2 新历史反事实：6 对、12 个 checkpoint 版本

另建版本，不覆盖原候选。每对只有一条早期授权或签名事实不同；当前请求与整个公开接口逐字相同。各成员的合法选择由各自公开前史支持，工具不能免费查询该旧事实。候选动作均可执行，不能依赖隐藏前提拒绝错误动作来泄露目标。

| 基础工作流 | 成对早期事实 | 对应相反的合法选择 |
|---|---|---|
| iw01 资料发布 | audience=internal / public | 对应受众交付 |
| iw07 会议出行 | hotel location=station / venue | 对应地点酒店 |
| iw09 恢复演练 | approved snapshot=s8 / s9 | 对应快照恢复 |
| iw08 账单通知 | authorized contact=email / SMS | 对应通知渠道 |
| iw12 库存计数 | carton size=10 / 12，10 箱 | 100 / 120 units |
| iw11 凭据留档 | issued credential=k9 / k10 | 对应凭据记录 |

公开规则允许单次提交，禁止先尝试错误选择再覆盖。`commit_count` 的实际增加与相关规则对所有条件相同；评分依据实际结果和已公开约束。离线穷举在至多四次动作/四 credits 的路线，确认每成员有合法路径，且没有一条相同动作序列同时通过两成员。该性质证明至少存在需要旧信息区分的选择，不保证两个 No History 模型响应相同：供应商服务仍可能具有非确定性，偶然猜中也可能发生。

历史差异、当前输入和接口哈希、公开来源事件、相反动作及穷举结果需在新数据 manifest 保存。不得把差异因素标签、隐藏目标值、评分、解法、未来段或整条研究者索引发送给模型。成员 `instance_id`、a/b 后缀、文件路径与实验分配信息只进入账本，不进入模型消息；如接口需要场景别名，同一 pair 使用相同中性别名。冻结前还要比较两成员 No History 的完整首请求体，而非只比较数据中的 `current_request` 字段。

**阶段 A 在任何阶段 D 模型成绩出现前锁定这 12 个反事实成员。** 它们来自六个相关基础工作流，不能写成 12 个独立任务。原 12 个候选只是 D 的另一分层，不根据模型成绩移入 A；A 也不根据 Full/No History 结果删除困难、容易或有利的成员。

## 3. D：Full 与 No History

固定 24 个输入：原候选 12 个，加反事实 12 个。每输入各分配 Full、No History，合计 48 cells，最多 192 次执行调用。原来的 96 请求建议仅适用于 12 输入×2 条件，不能沿用到本扩展矩阵。

- Full：当前公开请求、完整合法公开前史、共同公开接口。
- No History：同一当前公开请求与共同公开接口，不附旧事件、旧动作回执、参考摘要、历史来源值或研究者说明。
- 两者均从该 checkpoint 相同的隐藏世界快照分支，工具产生的本次真实观察只进入本条件。工具和当前公开信息可自行恢复事实；恢复成本按真实调用计入。
- 每 cell 最多四次执行调用，一次只能选择一个环境动作，`finish` 也消耗一次模型执行调用。四 credits 是环境操作额度，不是 API 调用数或金额。
- 正常模型错误、非法工具、错误完成和额度耗尽留在分母。没有状态提取或编码修复。

分别报告原候选与反事实，不合并后宣称全部任务需要历史。反事实按六 pair 报告两成员成功数、Full 双成员成功、No History 双成员成功、首个实际选择是否符合各自旧事实，以及配对前的请求体相同性。不能仅凭 pooled Full 成功数高于 No History 就声称每个任务具有历史必要性。

No History 成功可能是猜中、当前观察恢复、目录泄露或真实历史无关；需依来源与轨迹逐案区分。若某 pair 当前输入不相同、旧值由工具免费恢复或评分只能通过隐藏规则理解，则是任务/设施失效，停止并报告；不能删去该 pair 后保持本轮完整结论。未观察到行为差异不触发调任务、调提示或选择性补跑。

## 4. A：提取、额外推理与同信息呈现

六条件×12 固定反事实成员，共 72 cells；仍只有六基础工作流。全部条件获得相同当前请求、公开前史、未来变化支持范围及公共工具契约；只有执行前处理和最终活动表示不同。

共同语义指导要求保留当前有效目标、证据与适用范围、实际对象/操作阶段、重要依赖、剩余义务、资源和约束；既可用摘要也可用 CS 表达。不能把 G/W/F、JSON 字段存在或依赖图作为行为评分项。所有条件使用同一执行器，无免费参考状态或丢失历史回查。

| 条件 | 执行前处理 | 执行器活动输入 |
|---|---|---|
| Full | 无 | 全部公开前史 |
| Full+planner | 一次无工具规划，最多 1024 输出 Tokens | 全部前史与实际计划 |
| S1 | 一次强任务摘要，最多一次编码修复 | 最终摘要 |
| S2 | 一次无工具信息整理，最多 1024 输出 Tokens，再一次强摘要；最终最多一次编码修复 | 最终摘要，不免费另附整理稿 |
| CS1 | 一次 v0.3.1 CS 提取，最多一次编码修复 | 实际最终 CS JSON |
| CS-text | 与 CS1 共用实际源提取，确定性转换 | 同信息文本，无额外模型提取 |

S2 第二步读取共同原前史、当前请求/接口与前一步实际整理稿；再次读取原前史的全部输入成本计入。这样给两步摘要完整的信息源及额外推理机会，不人为先丢历史削弱它。执行器只读取最终摘要，不能免费另附原前史或整理稿。两步过程与其额外成本是被测竞争解释，不能把整理步骤带来的改善自动归因于状态结构。

S1、S2、CS1 的最终活动表示最多 6000 UTF-8 bytes；字节不是 provider Tokens。编码修复只能处理格式、引用/对象类型规范或长度，不能根据人工审阅补事实、删除错误义务、重写行为计划。未编码有效的源表示记失败，正常语义错误继续执行。

Full+planner 与 S2 organizer 的输出上限均为 1024 Tokens；其他模型调用最大输出 4096 Tokens。计划与整理稿不追加编码修复；响应为空或运行器无法读取时依冻结规则失败，不发隐式重试。每个有效活动输入最多四次执行调用。

### 4.1 CS-text 的解释和成本

转换规则必须在模型调用前冻结：保留每项键、值、对象身份、来源、阶段、依赖、有效性和原顺序，以确定性文本段落呈现。保存逐项对应或可逆检查，证明转换没有删信息、加入推断或替换行动。CS-text 可能比 JSON 更长，不能为了 6000 bytes 截断；按实际字节与 Tokens 报告。该对照只检验这套呈现方法，不等同“完全去除结构”，也不支持所有 JSON 与文本的一般因果结论。

CS1 源编码失败时 CS1、CS-text 同时失败，保留分母。有效但错误的源也同时继承，不人工修正。两条件从同一 checkpoint 世界独立分支，执行后不交换观察、完成事实或世界。

真实全实验账本只计源 CS 调用一次；独立部署的 CS1 和 CS-text 策略归属成本各包含完整源提取/修复。策略归属之和因此不是本实验实际花费，必须另列，避免 CS-text 被记作免费维护或全账本重复计费。

最坏实际请求推算：Full 48；Full+planner 60；S1 72；S2 84；CS1 72；CS-text 只增加执行 48；共 384。硬请求上限 400 不表示必须花满或允许超过每 cell 规则。

## 5. 来源审阅先于行为揭示

采用批量准备：先完成 A 的全部预处理和编码判断，一次导出仅含公开来源、实际中间稿及最终表示的包；60 份来源标注保存并验证/hash 后才运行任何 A 执行器。不先运行并记录 A 行为。准备与来源审阅期间不能读取任何当前 A 续做 trace、score 或隐藏 fixture；D 的已完成成绩可知，A 的分配和提示已在 D 前固定，不能据此修改。

36 份最终压缩表示必须全部来源审阅；Full+planner 的 12 份计划与 S2 的 12 份整理稿另列审阅，检查新增事实、义务和当前阶段。CS-text 按同源加转换完整性检查，不制造另一份独立语义标注。编码失败/未生成者为 `not_observed`，不能从审阅表或行为分母消失。

沿用六项来源维度：`entity_phase_confusion`、`unsupported_completion`、`invented_requirement`、`missing_pending_job`、`unsupported_reopened_question`、`missing_decision_dependency`；各项标 `correct`、`incorrect`、`ambiguous` 或 `not_observed`，并记录公开来源证据。额外记录旧 claim 未撤销与新阶段冲突的证据，不把“出现依赖字段”当作正确性。摘要按内容审阅，不因没有显式图而判错。

来源语义错误没有零错误 gate，不据此修复状态或排除任务。审阅者是参与项目的助手，不声称条件盲法、独立人审 gold。审阅可以看到表示形式，故结果解释保留这项限制。

## 7. 配置、预算和停止

配置固定 SiliconFlow OpenAI-compatible API、`deepseek-ai/DeepSeek-V4-Flash`、`https://api.siliconflow.cn/v1`、temperature=0、`enable_thinking=false`、timeout=60s、seed=20261004。沿用现有客户端取环境凭据，不在代码、日志、协议或请求快照保存 key。seed 只规定分配顺序，不承诺服务确定性。

| 阶段 | 固定 cells | 最大实际调用 | 硬请求 cap | 固定 provider Tokens 停止阈值 |
|---|---:|---:|---:|---:|
| D 原候选+反事实 | 48 | 192 | 192 | 500,000 |
| A 六条件 | 72 | 384 | 400 | 750,000 |

上述预算在任何 D 模型调用前固定；D 的 Token 停止阈值由最初草案 360,000 提升至 500,000，理由是完整前史输入可能较大，未使用本阶段模型成绩调整。预算须和运行器配置一致后冻结。请求上限在发送前检查；provider Tokens 在响应后才获得，达到阈值后停止后续请求，最后一次可能越界。这不是严格金额封顶。不要依据未查询价格估人民币费用。

每次请求记录唯一 attempt/response ID、阶段、任务、条件、调用类别、实际输入/输出/缓存 Tokens、可得费用、时间与成功/失败。缓存输入是输入的子集，不再次加到总 Tokens。没有 usage 标 unknown，不估成零。

API 错误、未知用量、冻结不匹配、消息泄露、设施回放不一致或预算达到，停止整个该阶段，保存已有分配和失败/未完成项；不自动重试、不选择性补跑、不重调提示。中断后的完整恢复要另立事前计划并保留原轮，不拼接样本。正常行为失败和语义错误不触发停止，计入全分配结果。

## 8. 结果、竞争解释和判定范围

主结果是实际任务成功、最终目标满足与公开约束；同时报告工具正确性、决策一致性、已标注重复工作、实际动作、credits、全部 provider Tokens、延迟、编码有效率、来源错误与未完成比例。合法额外行动可以成功，其额外成本保留；更早失败的低调用不能当效率优势。

按全部分配报告，不以成功、源正确或低成本筛样本。另报共同完整观测的配对差，不选择性排除行为失败。置信区间/显著性不是本次主判定；六基础工作流及两个版本相关，12 个版本、72 cells 不能当 72 个独立样本，单次每条件只提供开发诊断。六 pair 虽有不同业务名称，实际都是“一个旧事实决定两个不可覆盖的提交之一”的相同机制子图，不能描述成六种独立生命周期、依赖或义务机制验证；其他保留要求在这些工具中可能无法违反，也未因此得到区分性检验。

预声明解释：

- Full 不优于 No History：当前诊断未观察到行为上的历史需求；逐案区分猜中、可恢复性和当前信息充分，不由此断定所有历史普遍无用。
- CS1 比 S1 好，而 S2 或 Full+planner 达到相近或更好表现：额外推理是竞争解释，尚无状态结构独立价值的证据。
- CS1 与 CS-text 相同：本呈现对照未识别到独立作用，不否定共有信息；两者不同也只支持这一转换和模型的局部呈现效应。
- CS1 与 S1 不同：仍混合提取质量、信息选择和呈现方式，不能称单因素因果结果。
- 只在一个基础工作流或相关两成员观察到差异：保留为案例，不宣称泛化。
- CS 保留字节更少但完整总 Tokens/延迟更多，或被摘要以更好行为、更低成本支配：效率目标未获支持，直接报告负面结果。
- 成功差异由编码失败决定：是端到端策略问题，不能解释为认知内容必要性已经被证明。

重要结果无论正负及时报告，但不会因此删任务、补跑某条件或更改冻结提示。完成 D/A 后再根据证据提出另一个研究版本，不能把结果后的建议写回本轮事前协议。
