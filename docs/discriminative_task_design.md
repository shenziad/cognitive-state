# 区分性续做任务设计 v0.1

状态：**草案，待独立研究者审阅**。可执行 JSON 与内存环境已完成离线方案重放；2026-10-02 已完成真实模型预检 24 组合及完整单轮 72 组合。候选参考状态全部仍为 `pending`，不能作为人审 gold。

## 要区分什么

研究对象是定义中的任务相关认知状态：目标 G、世界认识 W、认知边界 F 是否保留了下一阶段所需的信息。任务应能检验**信息遗漏或类别混淆是否改变行动、成功率或必要工作量**。

这里“区分性”是构造目标，不是已经观察到 Summary 与 CS 的分数差。优秀摘要可以编码同样的信息；如果它更小且同样有效，必须接受这个结果。不能把摘要限制为仅列 facts，也不能因为输出带 G/W/F 字段就给予额外分数。

上一轮所有任务都能从当前手册取回推荐设置。新任务使旧目标、证据、已完成进度等历史信息无法由一个当前手册重建。新可观察结果只回答尚未解决的问题，不返还评分答案。

## 数据与构造单位

- 数据集：`exp001-discriminative-v0.1`，路径 [datasets/exp001/discriminative_v0.1](../datasets/exp001/discriminative_v0.1/README.md)。
- 8 组配对 × 2 个实例 + 2 个正对照 = **18 个任务**。
- 每个任务仍是同一任务中断后的续做，不测试任意未来新目标，也不宣称代表长期真实轨迹。
- 所有行动、交付和部署都只是内存状态变化，没有真实外部发送或系统操作。
- 每组使用相同的操作/观察定义、工具目录、费用与干扰历史。主要变化放在同一条关键历史消息中。
- G01、G02、W01、W03 的初始环境状态相同；W02、F01、F02、F03 的证据/执行状态随历史对应变化，以保持因果一致。工具定义相同不意味着执行后的观察完全相同。
- Full Context、Summary、CS 比较时，同一个实例内必须使用完全相同的环境。组内 A/B 是历史敏感性检查，不是表示条件之间的替代比较。

## 八组机制

| 组 | 主考察成分 | A/B 的关键历史差别 | 应保留的最小信息候选 | 可观察后果 |
| --- | --- | --- | --- | --- |
| G01 目标版本 | G | 原公开交付目标被撤销，改为私有审计 / 公开交付仍授权 | 当前目标版本、有效交付对象、撤销的承诺、未执行状态 | 交付目的地不同；按旧目标交付失败 |
| G02 硬约束与偏好 | G | 离线为硬要求 / 离线仅在延迟相同时优先 | 优化目标、不可违反条件、偏好优先级、候选性能 | 硬约束选离线；软偏好情况下选更快的云方案 |
| W01 更新信念 | W | 高置信缓存猜测被控制证据确认 / 被推翻并确认队列原因 | 当前证据、猜测是否已确认/否定、证据时序 | 选择不同修复；不能照抄旧高置信猜测 |
| W02 确定性与确认 | W | 控制诊断已确认 / 只有未经确认的信念 | 事实/信念区别、缺少的确认、行动前提 | 已确认可直接修复；未确认必须先诊断；盲目修复永久计入违规 |
| W03 更新假设 | W | 握手证实旧 v1 假设 / 握手确认 v2、推翻旧假设 | 权威观察、已过时假设、尚未执行的旧计划 | 部署不同解析器；不能将默认假设当作当前事实 |
| F01 调用边界 | F（也涉及 W） | 提交已发出、等待回执 / 提交仅写在计划中 | 已发出还是仅计划、在途调用标识、缺少回执 | 已发出应查询；未发出应先提交；重复提交失败 |
| F02 完成进度 | F（也涉及 W） | A 已验证、B/C 待做 / B 已验证、A/C 待做 | 完成集合、剩余集合、工作预算 | 剩余行动集合不同；重复已完成工作会耗尽预算 |
| F03 信息缺口 | F（也涉及 W） | 已知 A、缺 B / 已知 B、缺 A | 已获得结果、仍缺的结果、后续依赖 | 查询不同分支；重复查询会挤掉必要查询或封包行动 |

W02 故意允许“已经确认后仍再次确认”的保守方案成功，但记录额外成本。不能把所有额外查询都强行判为任务失败。F02 的两个剩余阶段可按任一顺序完成；F03 的两种正确设置顺序不要求文本匹配。读取工具目录后再执行也是有效路线。

两个正对照：

1. **Control01**：所需证据可从当前资格查询重新获得，用于检查基础工具使用能力。
2. **Control02**：工作已经全部验证，只差结束信号，用于检查 Agent 是否会对已完成任务继续操作。

## 具体例子一：同样提到“离线”，不同语义导致不同选择

共同信息：选择满足硬要求的最低延迟方案；延迟上限 3 秒。离线方案 2.0 秒，云方案 0.8 秒，两者正确。只剩一次选择机会。

- A 的最新要求：离线是 HARD requirement，禁止网络。可行最优方案是离线。
- B 的最新要求：离线只是延迟相同时的 tie-break preference。可行最优方案是云。

需要保留的是要求的强度与优先级，不是“出现过离线这个词”。这直接针对上一轮 10/12 个 CS 将小幅修改偏好放入 Constraints 的问题。

审阅：[A 历史](../datasets/exp001/discriminative_v0.1/tasks/disc_g02_a.json)、[B 历史](../datasets/exp001/discriminative_v0.1/tasks/disc_g02_b.json)、[A 候选状态](../datasets/exp001/discriminative_v0.1/references/disc_g02_a.json)、[B 候选状态](../datasets/exp001/discriminative_v0.1/references/disc_g02_b.json)。

## 具体例子二：行动计划与执行进度不能混为一谈

共同计划：提交 packet，再取回 job17 的回执；只能提交一次。

- A 的工具记录：提交实际发出一次，job17 pending，未观察回执。下一步应查询回执。
- B 的工具记录：提交只是计划，实际从未发出。下一步应先提交，然后查询回执。

仅保留“下一步提交 packet”会让 A 重复提交；仅保留“计划里有 job17”会让 B 查询不存在的调用。当前环境不会开放历史行动账本。查询失败后恢复允许得到最终成功，但额外开销和错误调用会记录。

审阅：[A 历史](../datasets/exp001/discriminative_v0.1/tasks/disc_f01_a.json)、[B 历史](../datasets/exp001/discriminative_v0.1/tasks/disc_f01_b.json)。

## 信息边界

| 文件/数据 | 谁可以看到 | 内容 |
| --- | --- | --- |
| tasks/*.json 的 history | 提取器；Full Context 执行器 | 截断前历史，包括关键证据和已关闭其他工作区的干扰记录 |
| references/*.json | 仅候选参考状态条件执行器及审阅者 | 助手制作的 G/W/F，全部 pending，不是 human gold |
| environments/*.json 的操作目录 | 执行器通过 observe 获取 | 可调用操作、观察资源、价格；不包含目标、rubric 或隐藏状态 |
| 当前观察响应 | 执行器执行 observe 后 | 合法的新证据；提取器不能预先看到 |
| environments/*.json 的 rubric/initial_state | 环境及评分器、审阅者 | 实际进度、目标检查、历史对应的约束；不直接进入模型输入 |
| review_cases/*.json | 离线构造校验、审阅者 | 可接受示例轨迹，可能含未来观察后的选择；绝不能进入提取器或执行器输入 |

`workspace/catalog.json` 是公共操作目录，不是推荐行动手册。不存在返回隐藏 task_success 的工具；finish 只记录结束状态，评分在执行完成后进行。历史资源查询返回 unavailable，不披露原始证据。

候选参考状态只使用截断前信息。例如 F03 不在状态里写尚未查询的另一分支值；W02 未确认侧不能提前把未来诊断当作事实。现有来源 ID 是状态块级范围，不是逐条主张的已验证引用，需要人工进一步审核。

## 评分

- **Task Success**：目标状态检查全部满足、正确结束、未发生永久记录的策略违规、未超过工作预算。
- **Final Goal Completion**：目标状态检查通过比例，包含任务要求的证据/进度检查。已完成对照的初始比例可为 1；仍必须正确发出 finish 才能任务成功。
- **Tool Usage Correctness**：工具形状和操作前提合法的比例；合法工具调用仍可能违反任务约束，后者单独记录。
- **Decision Consistency**：终态满足要求、约束遵守、结束状态正确三项比例；与 v0.1 的四项规则不同，不跨版本直接比较这个平均值。
- **诊断指标**：策略违规次数、重复已完成工作、不可用资源查询、工作 credits 使用量，以及完整行动步数。
- **API 成本**：仍以服务的真实输入/输出 Token 统计，分别报告首次 Executor 输入和提取+全部执行总量。环境 credits 是任务内工作预算，不是 Token 或人民币预算。

盲目修复后再补证据不能抹去违规；重复提交不能通过后续恢复抹去。另一个正确行动顺序和额外的合法确认不自动判失败。主任务与正对照应分开汇总，配对任务还应报告一组两个实例均成功的比例。

## 后续比较与消融

1. 先用独立审阅检查任务是否合理、历史是否足够、评分是否带隐藏要求，完善候选状态。再检查 Full Context 是否能解决；若 Full Context 也失败，先排查理解、工具或评分问题。
2. 保留有竞争力的普通摘要提示，公平比较 Full Context、Summary、自动 CS 和候选状态。记录实际表示大小；不能把相同字节上限称为长度完全匹配。
3. 做**字段消融**（例如移除 F）和**信息消融**（删除所有字段中的进度/信息缺口）两类干预。G/W/F 内容可能重叠；移除 F 后，Agent 可能仍从 W 重建下一步，不能预设 F 独立必要。
4. 增加表示预算梯度与重复运行，固定数据与提示版本。配对两侧用同一运行规则，报告成功率、违规、重复工作、成本；成功标准不奖励特定措辞。
5. 若三条件仍接近满分，保留结果，扩展独立场景与自然任务轨迹。不能不断调整任务直到 CS 赢。

当前只有四种原有输入条件可直接运行；消融是下一步方案，尚未作为新的 condition 接入。剩余薄弱点包括：只有合成场景、数字预算较强、关键线索较明确、一次续做、缺乏自然语言需求歧义及长期状态更新。
