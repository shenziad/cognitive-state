# Cognitive State v0.3 更新协议

2026-10-03：更新协议已有独立最小实现；两次真实预检完成，门槛未通过，后续比较停止。参见 [实现说明](v03_implementation_and_cycle3.md)及[第三轮报告](../results/analysis/research_cycle3_20261003/analysis.md)。以下协议仍是设计目标，局部检查不保证全部语义不变量。适用于 [v0.3 定义](cognitive_state_definition.md)。

## 输入边界

下一轮补充规则已冻结于 [对象生命周期规范](operation_lifecycle_v0.3.1.md)及[第四轮协议](cycle4_protocol_20261003.md)。更新时先匹配请求/作业/同步操作的身份和版本，再解释其阶段；submission.completed 与 job.accepted 可以同时成立。语义错误计为实验结果，不再与设施有效性门槛混用；当前旧运行器尚未实现该协议。

输入为上次实际保留 CS、真实动作及公开回执、新用户要求/观测、共同工具契约和当前资源。历史归档默认只供研究复核。若另设可检索记忆条件，访问权限与成本须预先固定。

先检查来源、对象、版本和权限。用户目标修改、工具事实观测、模型推断采用不同规则，不能用“最新文本获胜”统一处理。

## 更新顺序

1. 更新有权限且适用的目标要求；保留未被替换的约束，增加目标修订标识。
2. 按公共工具契约解释真实回执，更新实际操作阶段；保留必要 handle、部分或未知副作用。
3. 加入有来源的判断，推断引用依据；处理冲突、推翻和替代，证据不足时保持未决。
4. 对依赖失效判断的推断、义务和计划重新检查；目标更新后重新验证旧计划。
5. 根据有效要求及实际证据，更新尚未完成义务；明示的独立验证仍需执行。
6. 关闭已解决问题；新问题必须有决策相关性；重开旧问题必须有失效证据或明确验证要求。
7. 可选生成候选行动，检查当前前提、资源和硬约束；不可行时修改计划，不能修改事实以迎合计划。
8. 压缩无活跃用途的重复/过期内容，检查引用与一致性，保存活动状态及单独审计记录。

这是逻辑步骤，不要求每步一次 LLM 调用。格式构建、引用检查、预算计算和已知工具阶段转换可由代码完成。语义检查仍可能出错，不能充当事实真值 oracle。

## 状态必须维护的规则

| 规则 | 违反示例 | 处理 |
|---|---|---|
| 要求有来源 | 新增“必须查 ledger” | 无依据建议不能变成硬验收要求 |
| 计划不是完成证据 | 写“将运行 A/B”后标记完成 | 等待实际执行回执 |
| 接受不等于完成 | 异步请求 accepted 后直接封存 | 按契约保留 pending/handle |
| 已解决问题不无故复活 | 已知接受方又列为未知 | 检查是否有真实失效触发 |
| 假设不自行升级 | 多次重写后标为 observed | 保留 assumed，等待新证据 |
| 失效沿依赖传播 | 旧诊断被推翻，仍按旧原因修复 | 重评相关推断、义务和计划 |
| 副作用有连续性 | 超时后假定未提交并重复请求 | 保留未知阶段，按接口检查/幂等机制处理 |
| 行动满足当前资源 | 剩 3，计划先花 2 再花 2 | 标为已知预算下不可行；未知成本不当成零 |
| 停止需要完成证据 | 没问题可问就 finish completed | 检查全部有效要求与必要验收 |
| 删除保持依赖完整 | 删除事实却留下无依据计划 | 同步修改/删除相关活动引用 |

预算检查仅针对公开可核算成本及作用范围。无法估算的未来成本须保留不确定，不能宣称已证明整条计划可行。

## 审计与失败处理

研究记录保存输入状态/新事件 hash、版本、条目增删改、来源、问题关闭/重开理由、计划失效原因、全部校验与修复调用。活动状态无需携带全部记录。

`source_refs` 指向公开材料或保留的审计定位；`depends_on`、`requires`、`requirement_ref` 指向仍存在的活动条目。活动引用必须可解析，审计 ID 不能代替必要内容。

分别记录 JSON/结构错误、长度超限、语义冲突、缺少证据和执行错误。结构合法不保证语义充分。提取无法解析时，不得假装产生了新有效状态。

保留上次有效状态、修复重试或读取来源，均属于需预先规定的恢复策略；旧状态必须标明尚未吸收哪些新事件。为 Summary 提供对应的恢复机会与共同资源预算；所有原输出、失败和调用成本保留。修复不能看到隐藏答案、未来问题或额外历史。

## 未决设计问题

是否保存候选计划、何时增量更新优于重建、失效标记保留多久、来源元数据是否值得额外成本，均需实验决定。先固定规则和可审阅例子，再进行实现与门槛验证。
