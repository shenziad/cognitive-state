# 机制消融与端到端成本：下一阶段草案 v0.1

日期：2026-10-03。状态：**设计草案，未冻结、未执行**。本文件不修改 `cycle4-execution-v2` 或其研究协议。先完成第四轮的已冻结比较，再决定是否实施以下阶段；届时须另建实验 ID，冻结实例、提示、运行器、预算、分配顺序与分析代码。

本草案仅使用已产生的第二、第三轮证据。第二轮的强摘要尚未被 CS 超越，旧消融有跨字段残留信息；第三轮短历史下，修订 CS 的总 Tokens 约为 Full 的 2.20 倍。它们说明需要区分信息、编码、额外推理和维护成本，不能作为本草案所提机制的验证结果。见[第二轮报告](../results/analysis/research_cycle2_20261002/analysis.md)、[第三轮报告](../results/analysis/research_cycle3_20261003/analysis.md)。第四轮结果尚未用于本文件。

## 1. 将研究问题拆成可以失败的判断

下一阶段优先检验：在目标变化、证据失效和异步任务推进中，显式保存对象状态、证据依赖及未完成义务，能否减少错误延续，并在计入维护成本后优于任务导向摘要。

三个判断分别报告：

1. **同信息编码的作用**：同一份保留信息，用 CS JSON 与语义等价文本执行，行为是否不同？这只检验编码和组织方式，不检验自动摘要的提取质量。
2. **语义信息的作用**：生命周期、依赖关系、未完成义务中，哪些内容对本任务续做有必要作用？这要删除所有同义表达，不能只删除一个字段。
3. **部署策略的作用**：自动 CS 在多轮维护后的行为与总成本，是否优于获得同语义指导的强摘要？成本包含每次更新、修复、失败和执行。

额外一次模型调用是否解释改善，是单独的竞争解释。相同调用次数不意味着相同内部计算量；当前 API 未提供可比较的内部推理成本，因此只比较观测到的调用、输入、输出和延迟。

## 2. 公平条件与任务来源

使用另行构建和审阅的工作流，先写用户要求、公开工具契约、事件过程、完成标准，再评估各表示需要什么信息。不要复制已看过的 cycle4 模板并称其为独立验证。首批至少覆盖目标修订、证据/版本失效、异步对象及迟到回执、跨步骤依赖、重复工作风险、资源作用域六类情形；每类两个工作流作为小规模机制诊断。每类的两个实例应有不同事件结构，不能只替换颜色或对象名。

强摘要与 CS 都获得同一份语义指导：有效目标、证据依据及适用范围、实际请求/作业阶段、关键依赖、剩余义务和资源。强摘要可自由组织任务相关信息，不强制使用 G/W/F 或 JSON。各执行器得到同一公共工具契约与当前消息；不免费恢复已丢弃历史或共享其他条件产生的观察。

共同执行器、模型及 API 配置在新实验前冻结；首轮建议沿用第四轮的模型、temperature 0、thinking=false。每个续做最多四次执行调用，压缩最多一次编码修复。修复只处理编码，不按语义审阅结果补事实或规划。实例必须在该执行上限内有公开可解路径；离线可解性不能当作模型成绩。

未来变化的支持范围可以公开，随后实际事件、隐藏世界和评分不能给提取器。压缩链只接收上次实际保留表示及新真实事件，条件之间各自继承真实世界。行为错误仍按共同恢复规则继续，表示不可续做时后续 skipped 保留分母。

## 3. 阶段 A：最小提取、编码与额外推理矩阵

建议 12 个独立工作流的一个公开 checkpoint，各条件一次续做。先做单 checkpoint，可解释提取和编码差异；本阶段不声称检验长期更新。

| 条件 | 执行前处理 | 能回答的问题 |
|---|---|---|
| F | 完整历史直接执行 | Full 参考表现及实际成本 |
| F+P | 完整历史加一次无工具规划，执行器仍读取完整历史与该计划 | 额外规划是否已带来相近改善 |
| S1 | 一次强摘要提取，最多一次编码修复 | 有竞争力的自动摘要策略 |
| S2 | 一次任务信息整理，再一次强摘要提取；最终编码最多一次修复 | 增加一次推理能否消除 S1 与 CS 的差距 |
| CS1 | 一次完整 CS 提取，最多一次编码修复 | 自动 CS 策略 |
| CS-text | 使用与 CS1 相同的实际源状态，确定性转换为同信息文本后执行 | 保持信息不变时，JSON/显式编码是否有作用 |

F+P 的规划与 S2 的信息整理各限一次、最大输出 1024 Tokens；其余最大输出 4096 Tokens。任何中间响应异常直接保留为失败，不追加未声明的重试。S1、S2、CS1 的最终活动表示均限 6000 UTF-8 bytes；F+P 是增加规划的 Full 策略，其总输入不享受压缩预算。

CS-text 是**同信息文本编码对照，不是强摘要**。转换须保留每项内容、对象、来源引用、阶段、依赖及有效性；不调用模型、删事实、加解释或调整行动。转换采用提前冻结的字段到文本规则，公开逐项对照。其长度可能超过原 JSON，全部输入按实际字节和 Tokens 计量；本组不人为截断来制造信息差。源 CS 失败时 CS1 与 CS-text 均记失败，不只挑选成功源状态。

同一源提取只在真实调用账本计一次。另给 CS1 和 CS-text 各自独立部署时的策略成本，两者都包含这次源提取；不能把共享提取记为 CS-text 的免费维护，也不能在全实验真实总用量里重复计费。CS1 与 CS-text 从同一 checkpoint 分支，不能在分支后交换观察或世界状态。

最大实际调用推算：F 48、F+P 60、S1 72、S2 84、CS1 72、CS-text 新执行 48，共 384；建议阶段硬请求上限 400。六条件共 72 个分配组合，仍只有 12 个基础任务，不是 72 个独立样本。

解释时使用多个对照：CS1 优于 S1，但 S2 或 F+P 消除差距，削弱“状态结构具有独立价值”的解释；CS1 与 CS-text 不同只支持这套编码的效应；CS1 与 S1 不同仍同时包含提取与编码差异，不能称为单因素因果结果。

## 4. 阶段 B：跨字段的语义必要性诊断

本阶段是研究者编辑的受控诊断，不是可部署的自动状态生成器。采用阶段 A 的 12 个公开 checkpoint，重新各提取一份源 CS；所有分支共用该次源状态。源错误照保留，不把它修成正确状态。编辑者只看该 checkpoint 的公开输入和源状态，先保存干预及 hash，再揭示续做轨迹、未来事件和评分。

使用统一的诊断文本编码，将源内容分成可审计的语义条目。提前冻结标注和删除规则，记录每个条目的原字段、原文与概念标签；必要的分句只能拆开原文，不能加入推断。四个分支使用同一渲染器，消除 CS Schema 因缺字段或悬空引用报错的混杂。候选动作建议在所有分支均排除，避免行动答案成为免费补偿；因此本阶段的完整分支是明确记录的诊断版本，不能冒充未改动 CS1。

| 分支 | 删除的语义 | 必须保留或检查的边界 |
|---|---|---|
| 完整诊断状态 | 无；只有共同编码转换和候选行动排除 | 删除规则的共同参照 |
| −Lifecycle | 请求、作业、同步操作的实际阶段/结果及其同义完成、接受、待办陈述 | 保留对象身份与 handle；删除 claim、goal 注释、frontier 中重复的阶段事实 |
| −Dependency | 显式前提、因果/支持关系、证据有效范围及失效传播关系 | 保留独立目标、观察内容与对象身份；不能同时删除整份测量结果 |
| −Obligation | “还需做什么”的未完成义务及同义 pending 要求、未决问题/下一步提示 | 保留用户原始目标和实际世界；执行器可以重新推导剩余工作 |

一条内容属于多个概念时，记录交叠；拆不开而必须一起删除的条目标 mixed。这样的分支只支持组合信息干预，不能归因于单一机制。删除同一语义的所有副本，并同步清理已经失去内容的引用。检查 goal、claim、operation、question、candidate 及自由文本，避免第二轮“删字段但语义还在”的问题。

公开契约对全部分支保持相同，它可能帮助执行器重新推导信息；允许通过工具恢复的事实照常恢复并计入调用、Token 和资源。消融不降低成绩可能来自冗余或可恢复性，不能据此判定该概念普遍无用。完整分支若本来缺少待删语义，则该任务标“无干预作用”，仍留在分配总表，另报有实际变化的诊断子集。

未通过源编码的任务四分支均失败；有效源的语义错误不筛除。主要诊断报告四分支全分配成功数、工具恢复成本和关键错误；另报有效源条件下的配对差，清楚标出条件化。编辑耗时和人员介入单列，不能把它记作零成本自动压缩。

12 次源提取最多 24 调用，加 12 × 4 × 4 次执行，最大 216 调用；建议请求上限 240。完成全部干预审阅之前不启动任何分支；不得看到某分支失败后重写编辑。若 source 内容无法按冻结规则进行干净干预，应报告无法识别的机制，而非继续删到显著失败。

## 5. 阶段 C：多轮成功率—总成本曲线

只有前面给出值得检验的机制线索、或第四轮提出明确更新问题后，才另行冻结本阶段。使用四条新的独立工作流，每条四次交接；它们不得参与阶段 A/B 的提示修改。建议最低矩阵如下：

| 变量 | 水平 | 固定条件 |
|---|---|---|
| 策略 | Full、强摘要、CS | 强摘要与 CS 获得同语义指导及相同修复规则 |
| 初始历史长度 | 约 4 KiB、约 32 KiB UTF-8 | 所需关键事件不变，增加独立、已结束的无关工作片段；不插入隐藏答案或干扰指令 |
| 压缩预算 | 2000、6000 UTF-8 bytes | 仅对强摘要和 CS；Full 不重复跑两个无作用预算 |
| 交接次数 | 第 1、2、4 次前缀 | 从同一四段实际链读取累计结果，不额外重跑短链 |

完整分配：Full 为 4 × 2 × 4 = 32 段；强摘要和 CS 为 4 × 2 × 2 × 4 × 2 = 128 段；共 160 段。每段 Full 最多四次执行、压缩最多两次提取及四次执行，理论请求上限 896，建议硬上限 900。

长短历史应保存事件级对应表，由公开语义审阅确认关键内容相同；初始工作流、目标变化和未来公开事件一致。后续世界是各条件实际行动产生的世界，不能重置到参考轨迹。相同工作流的两种历史和两种预算是配对版本，不算新的独立任务。四条链仅用于试探曲线，无法保证统计功效或证明等价。

每个前缀报告全部段成功率、整段前缀全成功比例和累计成本。绘制观测成功率与总 provider Tokens 的散点/连接线，同时展示失败、跳过和编码错误比例；明确标注基础链数。不能只展示成功任务的低成本，也不能把更早失败导致的少调用算成效率优势。

如需扩大到具有正式推断能力的样本，先用本阶段估计方差与配对错误结构，再另行决定独立工作流数、可接受性能损失及统计分析。不得看完四条链后宣布一个新的“非劣效界值”。

## 6. 预算与成本的统一记录

6000 bytes 是表示的字节上限，不是 provider Token 上限；JSON 标点、转义、文本语言和来源映射都会改变 Tokens。`max_tokens` 限制输出，不能保证最终活动表示具有同样输入 Token 数。共同提示、工具契约、来源权限元数据、消息封装及新事件均属于真实输入。

每个实际请求保存阶段、任务、条件、提取/整理/规划/修复/执行类别、唯一响应标识、成功或失败、输入/输出 Tokens、缓存输入、耗时及可获得的服务费用。缓存输入是输入的子集，不在总 Tokens 中再次相加。服务未返回用量时标 unknown，不能当零或使用估计冒充已测值。

策略总成本为所有初始化、更新、修复、规划、恢复与执行调用之和，包含失败和中断前已花费用。除了全分配总成本，报告共同有完整观测的配对差，不能以任务成功筛选配对。共享调用实际总量只计一次，策略独立部署成本另表归属。未测的检索、人工编辑、训练或存储成本标明未测；有需要时额外测量，不能默认为零。

建议成本上限仅作为后续冻结的起点：

| 阶段 | 硬请求上限建议 | 累计 provider Tokens 停止阈值建议 |
|---|---:|---:|
| A | 400 | 750,000 |
| B | 240 | 350,000 |
| C | 900 | 2,000,000 |

请求硬上限在发送前检查。provider 用量通常在响应后才得到，因此 Token 阈值只能在达到后停止后续请求，最后一条可能越界；它不是严格金额封顶。需严格金额上限时应另外使用供应商额度控制，不能仅靠日志阈值保证。三阶段分开启动，不把建议上限视为应花完的预算；模型和现有 API 的未知实际价格不在此估算人民币。

未知用量、服务中断、设施不一致、预算到达导致分配未完成时，保存全部结果并停止该阶段；不选择性补跑失败组合，也不发布完整性能结论。正常模型失败和状态语义错误计入成绩，不触发调提示。

## 7. 预声明的负面或削弱假设结果

以下判断要在新实验冻结文件中保留，无论结果方向：

- CS 只比 S1 好，S2 取得相同或更好的行为与更低总成本：额外任务推理是足够的竞争解释，结构独立价值尚未得到支持。
- CS1 与同信息 CS-text 没有可重复差异：本编码方式的独立价值未得到支持；这不否定被两者共同保存的信息。
- 语义消融只在有交叠、残留或源错误的任务中产生差异：不能定位生命周期、依赖或义务的单独作用。
- CS 的优势只出现在已经看过的模板或只在一次任务出现：继续保持开发诊断结论，不声称泛化。探索性继续线索建议至少出现于两个不同工作流类别，仍不等同统计显著。
- 多次交接后错误累积使成功率下降，或 CS 在所有观测工作点被强摘要以更好行为和更低成本支配：当前长期维护/效率假设受到直接削弱，应缩小主张或停止该技术路线扩展。
- 成功率差异主要由编码失败造成：这是端到端策略问题，须报告；不能把它解释为必要认知信息已被证明不充分。
- CS 只缩短保留文本，却没有降低完整总输入/输出、实际费用或延迟：只能报告表示缩短，不能主张系统成本下降。

S2 优于 S1 也不自动证明额外推理解释全部差异；CS-text 相同也不证明任何格式都无作用。消融无差异只说明本任务及接口未识别到作用。所有解释都应以配对案例、公开来源和成本账本支持，不以字段存在或命名支持。

## 8. 实施前的具体交付与选择

第四轮完成后先记录哪些结论与问题确实出现，再决定实施 A、A+B 或继续暂缓 C；任何变更在新版本明确说明，本草案不追溯成为第四轮事前协议。

准备新执行版本时交付：独立任务及审阅记录、共同语义提示、六条件完整消息、确定性文本转换规则、语义干预规则与编辑审计、世界继承/公开输入/来源权限/评分回放检查、成本归属与停止实现、固定顺序及全部资产 hash。每个设计诊断阶段须有自己的任务数、失败分母和结论范围。

目前没有实现这些运行器或发送新请求。本文件提出的小矩阵用于选择下一项能解释结果的实验；它不声称已有机制证据、功效保证或成本优势。
