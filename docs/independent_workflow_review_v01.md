## 4. 审查发现及修复核验

审阅期间作者修改的是没有模型调用的候选草稿。以下问题已修复，不作为最终版本的阻断项：

| 早期问题 | 最终核验 |
|---|---|
| iw06 目录给出尚待查询的实际单位，先读要求不够明确 | 目录不再给值；用户和公开前提显式要求先读签名通知 |
| iw02 先读要求及正确诊断选择过于隐含 | 用户要求和两个改动的公开前提均有 trace_read；错误候选操作也被明确定义 |

| iw10:h2 无条件声称之前 fit 已发生，可能赠送错误事实 | 改为 “if a v1 fit actually ran”；保持以本条件实际回执确认为准 |

## 5. 可解性、继承与恢复边界

内存重建和已有记录一致：48/48 规范路线成功、48/48 初始过早 finish 反例失败、16 个可执行的禁止动作反例失败。另有 2 次提前撤销旧凭据尝试被操作前提拒绝，收费且不产生效果；现有评分不将它们记为 `forbidden_action`，不能说已经测量所有禁止尝试。

48 条路线包含 finish：35 条为 2 动作，10 条为 3 动作，3 条为 4 动作；均在 4 credits 内完成。只要一次模型调用执行一个动作，规范路线符合最多四次执行调用的建议。工具知识已在目录中，offline 路线证明有可行路径，不能证明模型会找到它。

外部补丁仅在 iw10:h2 处理队列 v2 与下游有效性。旧 fit 结果并未被抹成“从未执行”，独立审计也没有失效。其他链无私自成功补丁；真实条件必须携带自身世界，不能载入下一段 canonical initial_state。

任意前段失败后的恢复尚未被证明。例如 iw06:h1 若完全未做，后段可能需要重新获取通知、纠正单位、校准并补多项检查，超过四次执行调用；原资源还可能不在后段目录中。未来协议须事前定义：哪些资源继续可读、如何补未完成义务、何时受阻、永久损坏怎样计入整链分母。不能只给失败条件补资源或把它重置为规范世界。

异步任务在本环境中由确定性 collect/confirm 操作得到终态，没有真实等待、失败分支或随机调度；版本和旧回执是语义事件。可把它作为对象/阶段记忆诊断，不能从其成功推断真实异步系统可靠性。

目前没有实际提取或表示输出；6000 bytes 等活动状态预算的编码可用性、provider Tokens 和修复率尚未测量。候选的四 credits 是虚拟工作区操作额度，也不是四个 API 请求或费用的保证。

## 6. 成绩与额外工作的成本

评分依据实际世界与公开业务边界，没有要求和 offline 路线完全一致。作者记录的 iw01:h2 多做一次合法设置后仍成功、费用由 2 到 3，已随全部主资产回放一致。

本次另做只读探测：iw03:h1 提前 collect_west、iw04:h1 提前 check_landscape_rights、iw07:h1 提前 confirm_hotel，均仍成功，费用由 1 到 2。**合法额外行动仍成功本身不是评分 bug**；它保留了多种有效路线，效率差要由真实调用、费用、动作数及后续收益判断，不能强制改成能力失败。

iw10:h1 额外 fit_v1 也仍成功，费用由 1 到 2，`repeated_work_count=0`。该指标只检测 fixture 明确设置的 repeat_key，不覆盖所有语义重做。报告应称“已标注类型的重复次数”，或另作轨迹语义审阅；不能由零计数推断全部没有重复工作。

反过来，违反已公开的一次操作要求或证据支持要求的额外行动确实失败：iw12 重下补货订单破坏 reorders=1，iw02 无依据时间修改破坏 timestamp_patch_applied=False。能力和成本必须一起报告，提前失败后的低用量不能算效率优势。

## 7. 候选任务的研究区分能力

这批任务并非全部同模板换名：iw03 有双对象与迟到状态，iw04 有取消请求和终态区分，iw10 有版本失效及独立审计范围，iw07 有部分偏好修订，iw12 同时包含既有物理动作、更正和在途订单。它们的事件与依赖结构存在实际差异。

仍有明显相似子图：iw02 与 iw06 都是修正后增加两项验收再放行；多个工作流包含 accepted→collect→验证/交付。四段固定、Boolean 状态、静态正确操作和相同办公室旁支使作者模式很强。统计单位应为工作流，并注明共享机制类别；48 段不能当作 48 个独立样本，这批候选也不能被命名为自然生产或研究者独立 held-out。

**最需要补的是历史必要性诊断。** 后段消息常重述约束，公共目录固定包含对象名、结果和所有前提，规范世界保留的状态也可让一个当前操作直接成功。iw08:h4 的 close_ticket、iw09:h4 的 restore_production_s8 是明显例子。四段成功可能主要说明环境保留了工作状态，而没有要求模型记住足以改变选择的过去信息。

正式主比较前至少采用 No-History，或成对改变早期偏好/对象映射同时保持当前消息一致，检查哪些后续选择真的需要历史。关键事件删除诊断要同时防止当前目录免费补回同一信息。无需让每个段都依赖整段旧史，但需要给出预先声明的历史依赖点、相应相反行动和评分标准。

这不是当前任务构造错误的自动证明；它决定该集可以承担哪种研究主张。通过工程审查与规范回放尚不足以承担 Cognitive State 相对强摘要的长期保留优势结论。强摘要仍须获得同语义指导、可表达所有信息，并计入相同维护/修复规则。
