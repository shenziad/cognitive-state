# 独立工作流候选任务 v0.1：设计与审阅

日期：2026-10-03。状态：**新构造、可审阅、未冻结、未调用模型**。

本候选集从十二种可解释的业务工作流及其验收标准出发，再构造四次交接中的变化。它用于下一阶段的任务设计审阅，尚未成为正式模型实验。作者是已参与本项目开发的助手，“独立工作流”指新的工作流实例，**不表示独立研究者构造、自然生产数据或正式 held-out**。

设计依据是 [research_question.md](research_question.md) 中限定的未来延续范围，以及 [cycle4_protocol_20261003.md](cycle4_protocol_20261003.md) 的共同信息、行为评分和真实世界继承原则。此文件没有改写第四轮协议、任务、提示或评分，也没有根据第四轮新成绩挑选场景。

## 从业务验收到事件变化

每条工作流的目标是一个实际可理解的交付物。成功由执行后的世界、业务约束、必要证据及 `finish` 状态共同决定，文本是否拥有 G/W/F、JSON 字段或依赖图不进入行为成绩。

| 工作流 | 最终业务结果 | 四段变化与容易丢失的信息 |
|---|---|---|
| iw01 科研资料发布 | 带引用、去除参与者表、在正确时点发布资料 | 构建→延期与通知→去除受限内容→发布；延期只改变时间，保密与引用要求继续有效 |
| iw02 认证故障处理 | 两类回归通过后关闭工单 | 错误诊断纠正→服务端验证→追加移动端验收→关闭；诊断被推翻不抹去已完成且仍安全的防护 |
| iw03 成对实验数据导出 | 两个正确对象的当前结果完成验证并交付 | 东区结果→西区结果→双验证→交付；不同作业的成功和迟到旧状态不能替代当前对象结果 |
| iw04 渲染期间撤回同意 | 确认人像取消后，仅发布有权限的风景资产 | 提交取消→确认终态→验证替代资产权限→发布；请求返回与作业取消范围不同 |
| iw05 持续文献综述 | 根据更正与撤稿重新分析并发布综述 | 纳入更正研究→去除撤稿并重算→更新叙述→发布；筛选已完成的事实不因结论失效而消失 |
| iw06 仪器校准交接 | 纠正单位并完成两类校准验收后放行 | 单位更正与校准→标准校验→追加负载校验→放行；保留原始采集、分辨测量解释与物理行为 |
| iw07 会议出行变更 | 已订列车、无障碍会场酒店及接送形成正确行程 | 初选酒店→只改位置偏好并确认→增加接送→发送；位置偏好变化不撤销无障碍要求 |
| iw08 客户账单更正 | 单次退款、正确账单和税额已通知并关闭工单 | 等待已有退款→开具与核税→通知→关闭；旧账单/其他退款回执不能更新当前对象，服务仍需保持 |
| iw09 备份恢复演练 | 正确快照经校验和演练后用于生产恢复 | 获取快照→读签名清单并恢复预演→演练→生产恢复；结果版本、校验和、已完成演练跨段相关 |
| iw10 可复现队列分析 | 当前队列版本的模型、表格与报告完成 | v1 拟合→队列更正与 v2 验证→v2 表→报告；下游结果失效，独立且仍有效的隐私审计保留 |
| iw11 生产凭据轮换 | 新凭据测试、客户端切换、旧凭据撤销并留档 | 收取与测试→切换→获准撤销→记录；发行接受不等于可用，撤销许可仅改变时点限制 |
| iw12 库存对账 | 更正账面计数，使用原始调拨与当前补货完成对账 | 读包装规格更正→收取已有补货→对账→报告；计数解释变化不能导致再次物理调拨或重复下单 |

关键变化均以用户更新、外部更正、对象明确的回执或付费可读资源出现。工具目录只说明操作契约和可能成功的效果。尚未读取的资源内容仅在隐藏 fixture 中，真正观察后才进入模型材料。

iw03 第一段要求本段取得东区结果，允许提前取得西区结果，没有东区操作必须先于西区操作的硬顺序。两者独立验证只在最终成对交付前需要；离线路线先取东区只是其中一条可行路线。此措辞与按结果评分的 rubric 一致，避免把没有评分的严格先后要求暗含在 “first” 中。

不同条件都可用文字保存这些内容。强摘要可以完整表达目标变更、保留约束、对象身份、证据有效性、执行事实、未决义务和跨段依赖。本任务集没有设置只有结构化 CS 才能使用的工具、免费回查、参考状态、额外语义修复或字段加分。

iw02 和 iw06 的用户要求及工具前提明确说明先读取当前诊断/签名通知，再进行改动。iw02 提供缓存与时间转换两个可解释的候选改动，只有已读证据能支持相应诊断；iw06 的目录不透露通知中的实际单位值。这些场景主要检验证据获取、遵循流程和跨段保留，不能单独证明状态改善开放式信息选择或领域推理。

## 文件与输入边界

候选目录为 [datasets/independent_workflows_v01](../datasets/independent_workflows_v01/README.md)，由 [生成脚本](../scripts/build_independent_workflows_v01.py) 创建。脚本只导入现有 `LifecycleEnvironment`，不导入模型客户端，不读取凭据。

| 文件 | 用途与可见范围 |
|---|---|
| `public/iwXX/hN.json` | 单独一段的公开新事件与公共接口；没有未来段、隐藏状态、评分、答案或因素标签 |
| `public_workflows.json` | 研究者审阅索引，包含全部段与因素标签；**不能整文件发送给模型** |
| `evaluator_fixtures.json` | 评估器私有 world、外部补丁和行为 rubric；从不进入条件输入 |
| `offline_trajectories.json` | 可看到 fixture 的离线路线；只证明有合法路径，不是模型基线、输入或必须匹配的动作序列 |
| `offline_validation.json` | 现有环境上的继承、评分回放与反例记录；不含模型表现或 Token 结论 |
| `provenance.json` | 此前接触的因素、开发数据关系和审阅 hash；这是可重算的溯源信息，**不是正式协议冻结** |

未来运行器应从单段公开文件读取新事件与当前公共接口，在 Full 中加入实际历史，在压缩条件中加入该条件实际保留的表示及真实动作/回执。运行器不能把研究者索引、后续目标、隐藏 fixture、canonical 离线路线或未来资源值放进消息。

第一段的世界由场景给定，之后每个条件继承自身实际动作后的世界，并仅应用该段事先声明的外部补丁。本候选集只有 iw10 第二段的队列更正带外部补丁。后续公开事件没有声称前一段模型已经完成某个动作：完成事实须由本条件的真实轨迹提供。fixture 中各段 `initial_state` 是**离线成功路线的参考起点**；真实实验不得用它重置一个失败条件的世界。

后续用户更新均明确：未撤销义务继续有效，缺少的工作仍要完成；“保留”是一项要求，不是完成证据。iw10 的旧拟合执行事实与 iw03 的东区结果也使用条件化措辞。因而前段早结束时，后续材料不能凭空赠送执行成功。现有检查另以未产生任何执行效果的前段世界复核 36 个后续接口，它们不依赖 canonical 成功起点；自然语言的事实一致性仍需要人工审阅，不能由接口相同自动证明。

公开新事件每条工作流共包含 42 条办公室协调旁支记录（第一段 24 条，后三段各 6 条），穿插于业务事件之间，且没有被包装成用户约束。它们只是审阅阶段的固定干扰原型，不能被解释为真实长历史、多档历史长度或成本曲线。其重复和人工模式可能让任务过于简单；正式使用前应由审阅者决定替换、减少或按预先规则拓展。

## 已完成的离线检查

12 条工作流、48 个交接段均有合法路线，使用 **现有 `LifecycleEnvironment`** 按真实执行世界逐段回放。每条路线包含 `finish`，在 4 credits 以内完成，未出现重复工作、工具无效或约束违约。

- 48/48 路线满足实际目标与合法完成条件。
- 48/48 接口隔离检查：更改隐藏 world、rubric 和未读资源值不改变公开接口。
- 48/48 过早 `finish completed` 反例不能得任务成功。
- 16 个可执行的禁止动作反例不能得任务成功。
- 2 个凭据提前撤销尝试由操作前提拒绝，收费且没有成功效果；它们单列为前提阻止。
- 36 个后续段在前段未执行任何操作的反例世界中，公开接口仍相同且没有重置世界。
- iw01 第二段增加一次合法设置动作后仍得任务成功，实际费用从 2 增到 3 credits，验证成绩没有要求匹配 canonical 路线。

这些检查只证明已编写路线与环境逻辑相容，不能证明模型能找到路线、状态能维持充分性、所有错误后都能恢复，或某种表示有优势。所有 48 段仍来自 12 条相互关联的链，不能当成 48 个独立任务。

现有评估器在操作前提失败时，记录工具无效和实际费用，未产生作用的禁止尝试不会进入 `forbidden_action`。因此“有害效果未发生”和“用户禁止的尝试是否发生”尚不是同一指标。正式新协议应明确是否单独评价尝试违规；本草案记录边界，**没有修改现有或已冻结的评分**。

合法额外行动只要不破坏业务目标、显式约束或额度，可能不降低 `task_success`。这允许多种有效路线，并保留其实际调用、费用、动作数与标记重复工作作为辅助结果。单次多做一步不是必然行为失败；后续机制分析不能只按成功率筛掉额外工作的成本。当前 `repeated_work_count` 仅识别 fixture 明确标注的重复类型，不是所有语义重复操作的完整检测器。

生成器通过程序性检查确保公开接口不受隐藏值影响，但尚无正式模型消息适配器；在真实调用前仍需测试每个发送消息的完整投影和未来事件隔离。一次规范路线成功也不能保证在任意前期行为失败后未来阶段仍可完成。错误后恢复、永久损坏与后续分母规则需要在下一版协议中明确。

## 与已查看开发任务的关系

本作者此前知道 cycle2/3 中目标修订、证据/假设区分、重复工作、pending 义务、分散依赖等因素；也阅读了 cycle4 的请求/作业/同步操作、对象和结果版本、独立验收及迟到状态规范。现有 Boolean world 和动作目录也影响了任务实例的实现方式。

本集未复制旧轮的实例、历史、目标、fixture 或离线路线，业务名称和具体事件均新写。这仍只是**开发知情的新任务构造**。不是结果未知就自动成为正式 held-out，也不能从未调用模型推导作者独立。若随后根据成绩调任务或提示，必须保存本版及修订理由，并建立新的实验版本。

这十二条工作流把现有机制嵌入不同业务叙事，但仍有固定四段、简化状态、静态操作、合成旁支及短解路线等共同人工模式。条件看到的目录明确列出了成功效果和前提，这降低了操作知识难度。真实任务中的开放式文件修改、检索质量、可观察失败、长时等待与模型自创工具计划尚未覆盖；不得用这批成绩主张自然长期 Agent 的总体优越性。

更直接的研究限制是**历史必要性尚未证实**：用户更新常重述约束，目录也固定给出正确对象、结果和动作前提。规范世界下，iw08 第四段的关闭和 iw09 第四段的生产恢复可能只凭当前指令和一个操作即可完成。四次交接成功可能主要依赖外部环境保留状态，并不能自动说明模型表示保存了历史。因此正式协议前须加入 No-History 诊断，或成对删除关键旧事件、改变早期偏好/对象映射但保持当前指令一致的反例，验证真实行动选择确实依赖过去信息。任务无需让每个段都需要全部旧史，但必须明确哪些后续决策、依据什么历史才可区分。尚未做这些诊断，本版不能作为 Cognitive State 具有持续保存优势的验证集。

## 进入新实验前的决定

先审阅业务规则和公开事件在前期失败条件下是否仍真实成立，确认哪些约束应跨目标变更保留、哪些验收显式新增。再确定要检验的主要主张、任务抽样单位、历史长度与表示预算、强摘要指导、重复次数和允许误差。固定协议后才编写适配器、条件提示和运行顺序，并冻结完整输入/评分/配置/来源。

若要分析机制，可在主比较完成后增加生命周期、证据依赖或义务信息的消融；消融不能只把某个字段从 JSON 删除却保留同义内容，也不能把更长提示或额外推理混同为结构的作用。本版只准备候选任务，不声明这些后续实验已注册或已获验证。

若要建立更强的独立验证，应安排不了解模型成绩的人从业务规范出题，再在接受实例之后锁定提示；也可以引入公开可复现的自然工作流。当前候选集适合作为可审阅起点，不承担这样的证据角色。
