# v0.3 修订说明与审阅入口

2026-10-03 设计修订记录：本文件最初产生于用户暂停实验期间，当时仅改文档与示例。此后用户授权继续三步工作，已完成独立最小实现与两版真实预检；比较门槛失败，见[第三轮报告](../results/analysis/research_cycle3_20261003/analysis.md)。以下保留设计修订的原始论证，不能将设计目标当作已证实机制。

建议先读 [Cognitive State 定义](cognitive_state_definition.md)，再看 [更新协议](state_update_protocol_v0.3.md) 和 [有来源的前后状态示例](examples/cognitive_state_v0.3/README.md)。实验推进条件见 [实验设计](experiment_design.md)。

## 结果如何影响设计

| 现有证据 | v0.3 修改 | 尚未证明的内容 |
|---|---|---|
| 已知 pearl 接受，却新增 ledger 必要性假设和身份缺口 | 判断有来源；问题重开需要失效事件或明示验证要求 | 无依据确认的唯一成因；新规则能否减少错误 |
| 局部修复 Next Action 后仍先付费查 ledger | 候选计划可省略；W/F 一致性与依赖一起检查 | Frontier 无用；删除计划一定更好 |
| Full 正确消费后仍查询，旧回执未明确 fulfilled | 所有条件共享明确的公共效果和成功回执 | Full 的失败只由回执造成 |
| CS 在严格字节预算下频繁失败，两个连续链首提取即失败 | 活动语义与编码分开；先做提取可靠性门槛 | 语义容量不足；CS 长期演化一定失败 |
| 删除某字段后，其他字段仍保留相同信息 | 以语义单位和依赖关系设计消融 | 被删除字段无必要性 |
| Summary 单个成功链总 Token 下降，但未缓存输入、输出与耗时上升 | 分别记录表示规模、实际输入/输出/缓存、更新恢复成本及延迟 | 实际金额更低或总体效率优势 |

上述证据来自 [第二轮总报告](../results/analysis/research_cycle2_20261002/analysis.md)、[单案例](../results/analysis/frontier_case_v02_20261002/analysis.md)及[连续交接](../results/analysis/longitudinal_v01_20261002/analysis.md)。它们为小型探索结果；设计推论不是因果结论。

## 提示与实现要求

旧提取提示要求 identify the next evidence-seeking action，可能诱导不必要调查。新提示应允许没有信息缺口、直接执行、等待或完成；要求先检查现有证据是否已解决问题。该关联尚未单独实验验证。

未来实现时应做到：G 要求有来源；W 操作阶段由公开回执支持；F 未决问题有决策相关性；计划满足当前前提和预算；新目标/观测触发依赖更新。结构与引用检查可以程序化，语义校验不能假装无误。

本次没有覆盖旧 prompt，以免同名配置无声改变行为。未来实现须新增 state schema、extractor/updater、prompt 和任务接口版本，提供明确的入口校验；不把 v0.3 示例送入现有 v0.2 parser。版本转换不能假装获得旧表示未保存的来源或操作证据；缺失信息应显式标明并按预定恢复策略处理。

## 保留与改变

- 保留 G/W/F、任务条件化、外部表示、行为能力评价以及 API-first、不训练模型的阶段路线。
- facts/beliefs/assumptions 的概念差异继续保留，表示为判断的依据类型；主观 confidence 不再强制填写。
- Frontier 的核心改为未完成义务与真正影响选择的问题；候选行动成为可选、可失效的计划。
- 增加证据有效性、重要操作阶段、资源范围和更新规则，而不是增加更多宽泛模块。
- 状态长度最小化限定于明确任务延续范围和恢复接口；研究归档与活动输入分别统计。

## 审阅重点

1. 已知、已完成、必须重查三者的判据是否足够明确？
2. 示例是否只使用该时刻可见的材料；公共契约是否足以支持 finish 判断？
3. 哪些来源/失效/操作元数据值得进入活动状态，哪些仅需保留在研究记录？
4. 是否可以用更少内容表达同样语义；与任务导向摘要相比，新增结构究竟提供什么可检验机制？
5. 下一轮可靠性和语义质量门槛、可接受性能损失、样本量及重复次数如何在调用前冻结？

当前没有给这些开放问题填入任意成功阈值，也没有声称设计已通过独立研究者审核。
