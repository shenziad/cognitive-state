# 连续四次交接：来源与行为关联

## 范围和审阅顺序

本阶段使用冻结的 `cycle4-execution-v2`，两个已知合成工作流、四条件、四次交接，共 32 段。所有段均启动执行器，无 API 错误、未知用量或编码修复。24 份压缩表示先依据公开输入完成并保存审阅，再揭示当前段行为；审阅者为同一研究助手，条件未盲化，不是独立人审 gold。

[review.json](review.json) 保留完整公开来源与状态，[audit.json](audit.json) 重放实际输入、世界继承、消息、评分和唯一请求，[semantic_behavior_notes.json](semantic_behavior_notes.json) 保存以下案例的轨迹、评分及证据 hash。

## 关键案例：已经完成的决定仍有未来价值

archive 第一段的真实诊断 `cedar-d1` 确认 right，随后 `correct_right` 实际成功，left 假设被反驳。第二段四条件都只提交一次作业，并在 acknowledgment 后停止；此时 `submission completed/accepted` 与 `job accepted` 正确分开，作业尚未完成。

Summary 第二段状态仍保存 right 分支及修复回执；第三段更新却只保留作业、当前完成/验证需求，丢失已确认的分支身份。第三段的作业完成和 A/B 验证都实际成功，但这些新回执不会重述早期诊断。第四段要求使用此前确认并修复的分支封存，且无新来源证据。Summary 状态明确承认缺少分支，执行器实际只调用 `finish(status=blocked)`，最终 `sealed_branch=unset`。

Full、两版 CS 均保留 right 身份，第四段实际执行 `seal_right`，再 `finish completed`。它们没有重做已接受的校验。这一案例说明：不能仅因一项工作完成就丢弃它的决策依据；其对象身份可能仍是未来操作的选择条件。

来源审阅将 Summary 第三、四段标为 `missing_decision_dependency`。第四段是继承此前丢失造成的缺口，不能算成第二个独立丢失事件；当前提取器无法从缺失的输入恢复身份。不把诚实承认缺口判成虚构、无依据重开或阶段混淆。

## 仍未解决的更新问题

v0.3.1 archive 状态逐步增加新记录，typed job 和 operation 阶段更新正确，最终 Frontier 也正确选择 right；但旧 claim 未完全撤销。例如最后一段仍同时包含“job 尚未完成”“A/B 尚未完成”的旧陈述与新成功记录，并保留此前 left 当前信念。来源 ID 能提示其历史来源，陈述却缺少明确的历史/失效限定。

本轮将这些记录为歧义，没有看到它们导致重做或错误封存。它们仍暴露出“加入新状态”与“撤销旧有效判断”之间的设计缺口。建议下个独立更新版本明确活动 claim、历史证据和失效传播规则，再在新任务验证；本轮不回写状态或调整分数。

## 可以支持什么

本案例提供“持续保留关键身份”的研究线索；两版 CS 都成功，无法证明新增字段、G/W/F 名称、依赖图或 JSON 格式的独立价值。没有随机删除 right 身份、没有同信息文本对照，也没有未见任务验证。H1–H3 尚未得到确认。
