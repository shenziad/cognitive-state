- 12 个合成配置修复场景；不能外推到长期真实 Agent 任务

## 首轮判断

**在这组短历史、合成配置修复任务中，自动 Cognitive State 可以支持任务续做，并降低输入 Token；普通摘要取得同样的成功率，且使用更少的 Token。本轮没有证明 Cognitive State 优于摘要，也没有找到最小充分状态。**

这是助手对冻结结果的首轮审阅，不是独立研究者评审。没有在观察结果后修改提示、修复模型输出或追加挑选性重跑。之前的余额不足记录和本次两任务预检均保留，未并入本轮性能样本。

## 行为与状态内容审阅

### 1. 自动 CS 出现一次成本增加，但成功恢复

在 `pilot07_staging_route` 中，Full Context 和 Summary 都先读取当前手册，然后修改 `route` 和 `model_revision`，检查并结束，共 5 步。自动 CS 先只修改 `route` 就检查，检查失败后重新读取配置，再修改 `model_revision` 并验证，共 7 步。

- Full Context：7,129 Token；Summary：4,430 Token；自动 CS：7,491 Token。
- CS 首次输入从 1,257 降至 630 Token，但端到端用量比 Full Context **增加 5.1%**。
- 自动状态保留了初始 `model_revision=r1`，后续手册也提供了推荐值。因此不能把这次绕路直接归因于提取遗漏；更可能涉及执行器对计划和新证据的处理，但单次运行不足以确定因果。

可核查：[完整历史轨迹](../../raw/exp001/siliconflow_round1_20261002/instances/pilot07_staging_route_r0_full_context.json)、[摘要轨迹](../../raw/exp001/siliconflow_round1_20261002/instances/pilot07_staging_route_r0_summary.json)、[CS 轨迹](../../raw/exp001/siliconflow_round1_20261002/instances/pilot07_staging_route_r0_cognitive_state.json)。这是效率问题，不是最终任务失败。

### 2. 不同有效行动顺序应得到相同成功评价

在 `pilot08_pagination` 中，完整历史先修改 `page_size`，Summary 和 CS 先修改 `cursor_mode`；三者都完成两个修改、验证并成功结束。评分器接受这两种路线。其余 10 个任务的三个核心条件保存了完全相同的动作/观察轨迹；这里的轨迹一致只是观察结果，并非成功标准。

### 3. 字段校验通过，不代表字段语义正确

全部 12 个自动 CS 都能解析为 G/W/F JSON，并符合大小上限；逐项审阅可见它们保留了目标、保护字段、失败尝试、当前手册路径、未确认信念和下一步读取证据的行动。

但 **10/12 个状态将 “Prefer a small, evidence-based change” 放入 Constraints**，仅 TLS 和 Queue 两个任务放入 Preferences。例如 [JWT 状态](../../raw/exp001/siliconflow_round1_20261002/instances/pilot01_jwt_units_r0_cognitive_state.json) 的 Preferences 为空。部分状态又把使用当前手册写成 Preference，说明字段分类尚不稳定。本轮没有软偏好与硬约束冲突的任务，无法观察这种混淆的行为影响。

信念的 0.6 置信度均来自历史，不能视为经过校准的模型概率。后续语义校验应检查证据来源及确定性类别，不能只检查 JSON 字段与数值范围。

### 4. 保存更多信息尚未显示更强行为能力

Summary 在 Request Timeout、Staging Route、Log Redaction 三个任务中没有显式保留原来的未经确认信念，仍全部成功。自动 CS 保留这些信念，但本轮未显示它们的行为价值。许多摘要也继续描述了无关会议备注；CS 则没有保存这些备注。单凭遗漏/保留数量，不能判定任务相关性或检验 H2。

## 为什么目前无法检验核心假设

1. **任务有天花板效应。** 12 个场景共用“读取当前手册—修改配置—检查”的模式；手册包含所需推荐值，续做可重新获取答案。旧历史中的证据、错误信念及 Frontier 可能不是不可替代的信息。
2. **上下文仍很短。** Full Context 实际历史只有 2,734–4,301 bytes，首次 Executor 输入为 941–1,257 Token，包含共享执行提示与工具说明。本轮没有测试真正长历史或多次状态演化。
3. **数据和评分由同一助手制作。** 参考状态全部待研究者审核；没有独立真实轨迹和独立测试集。当前结论只适用于这组受控先导任务。
4. **一次重复不足以证明行为等价。** 全部成功不能排除更难任务中的性能损失，也无法估计状态效果的稳定性。两个 task success 都为 true，不意味着未来任务行为完全相同。
5. **未寻找最小状态。** 没有预算梯度、G/W/F 消融或状态元素删除实验。H1 仅有范围很窄的可行性观察，H2 未显示优势，H3 未被直接检验。

## 下一轮建议

优先提高任务区分能力，暂不训练模型或增加复杂系统。

1. 制作独立场景，使必要证据只能来自截断前历史，且不能由一个手册重新取回答案。包含新旧约束覆盖、已排除假设、失败动作、多个未完成子目标和软偏好冲突；保留合理的多条成功路线。
2. 增加状态消融：完整 G/W/F、移除 F、移除信念/假设、只留目标与事实。重点观察重复失败动作、违反约束、错误承诺和多余工具调用，以检验哪些状态成分支持继续行动。
3. 在独立任务集上比较多个表示预算，并对实际长度匹配或分层；做重复运行。固定提示后再运行，不根据本轮输出挑选成功案例。分别报告输入节省、提取开销、执行步数和端到端 Token。
4. 对“偏好被当作约束”等语义问题制定人工审阅表，审核候选参考状态。提示改进须使用新版本，与本轮冻结结果分开。

这些步骤完成后，才有条件回答“什么信息构成 Agent 可继续行动的最小认知状态”。
