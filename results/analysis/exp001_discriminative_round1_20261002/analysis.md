# exp001 区分性合成续做任务：单轮描述分析

模型：`deepseek-ai/DeepSeek-V4-Flash`；数据集：`exp001-discriminative-v0.1`；状态：`completed`。
本次选择 16 个配对实例（8 组 A/B）和 2 个 controls；每组合重复 1 次；保存 72/72 个组合。

## 本轮判断

**在这轮任务中，自动 Cognitive State 没有表现出优于普通 Summary 的优势。** 16 个配对实例上，Full Context、Summary、自动 CS 都是 14/16；CS 在一个正对照额外失败。不能把这轮结果解释成 G/W/F 结构已证明有效，也不能据此否定 Cognitive State 假设。

- 三种输入在 W/F 主任务中均保留了可继续行动的信息，执行分支与历史相符；这些任务尚未区分普通摘要与 CS。
- 7 次失败发生在执行阶段：6 次未执行选择就结束，1 次工具 JSON 形状错误后过早 blocked。没有发现可明确归因于关键状态提取遗漏的失败。
- 以全部 18 个任务的**同实例降幅宏平均**计，CS 初次 executor 输入减少 63.5%，计入提取和全部执行调用后减少 11.2%；Summary 分别减少 71.9% 和 27.8%。减少输入不等于等幅降低端到端成本。
- 待审核的候选参考状态 18/18 成功，但动作具体程度、来源缺口和未测量的制作成本限制了比较；它不是自动 CS 优越性的证据。

完整轮次使用 247 次真实 API 响应，共 292,427 个提供方报告 Token；另有独立预检 76 次响应、90,411 Token，不合并入本轮性能。两轮合计 323 次响应、382,838 Token。这是 Token 用量，不是货币账单；缓存命中和价格未折算。本轮无 API 或表示阶段错误。

## 解释范围

- 本报告只描述这一次小型、助手构造的合成续做任务运行；不能推广到长期真实 Agent 任务。
- G/W/F 是任务设计中的主要信息差异标签，不是组件消融或因果归因。
- 各条件的任务失败与提取/表示错误均保留成功率分母；provider/transport 中断使整轮性能与降幅不可发布。
- 未启动 executor 的提取/表示失败，其 steps、credits、违规、重复工作与不可用观察等执行诊断为 null；均值按已执行样本计算。
- Token 宏平均按可观测的 instance × repetition 计算，列出覆盖数量；失败样本已报告成本仍计入，未知用量不补零。
- 实际已报告 API 花费包含提取失败；降幅仅使用两条件都没有 error 且 Token 可观测的同实例配对，列出 n，不按任务成功筛选。低成本提取失败不能解释为效率优势。
- 初次输入是第一条 executor 请求的输入 Token；端到端包括提取与全部 executor API 输入/输出 Token。
- 候选参考状态尚待研究者审核，制作成本未测量；仅列已报告 API 成本，不计算参考状态端到端总成本或优势。
- 候选参考状态不是 gold：disc_w02_a 的 repair_queue 具体动作名不在关键历史中，含目录知识或作者推断；自动提取阶段看不到目录，存在参考来源缺口。
- ToolUsageCorrectness 只衡量 JSON/工具调用是否合法，不衡量行动是否符合目标；DecisionConsistency 是最终要求、约束合规、finish 状态三项均值，提前合法 finish 可在任务失败时仍得 2/3。
- repeated_work_count 是环境已记录重复工作；超过预算的重复尝试可能不计入。另列 posthoc repeated_work_attempts 与预算耗尽观察次数，未预注册且不改成功判定。
- W02 与 F01 存在统一查询后适应的策略；关键历史可能主要影响成本，因此 A/B joint success 不能证明历史信息不可替代。
- 相同表示字节上限不保证实际长度相同；UTF-8 字节不是提供方 Token。
- 本轮不进行显著性推断，不能证明 H1–H3，不能证明 Cognitive State 优于 Summary。

## 失败轨迹与替代解释

| 实例／条件 | 观察到的失败 | 证据及解释 |
| --- | --- | --- |
| G02 A：Full、Summary、自动 CS | 首步 `finish completed`，未选择 offline | 自动表示保留硬要求与正确选项；CS 明确记录未选择。支持执行遗漏，不能据此声称硬要求被摘要抹掉。 |
| G02 B：Full、Summary、自动 CS | 首步 `finish completed`，未选择 cloud | 自动表示保留 cloud 更快、offline 仅软偏好及正确选项；CS 明确记录未选择。支持执行遗漏。 |
| Control01：自动 CS | 读到 remote 资格后仍未选择，`finish blocked` | 表示合法，资源、操作名、先读再选步骤均已保留；执行器两次将 operation 放在 JSON 顶层，缺少 arguments 对象。 |

G02 的六条失败轨迹都只含一条合法 finish，计划仍为 none、credits 为 0。候选状态把下一步明确写为 `execute choose_*` 后成功；行动措辞的具体程度是混淆因素。需要在后续独立轮次中测量共同执行器的行动落实能力，而不是把差异直接归因于结构保留更多信息。原始例：[G02 A 自动 CS](../../raw/exp001/siliconflow_discriminative_round1_20261002/instances/disc_g02_a_r0_cognitive_state.json)、[G02 B 自动 CS](../../raw/exp001/siliconflow_discriminative_round1_20261002/instances/disc_g02_b_r0_cognitive_state.json)。

[Control01 自动 CS](../../raw/exp001/siliconflow_discriminative_round1_20261002/instances/disc_control01_a_r0_cognitive_state.json) 的 6 步：编造资源路径 `workspace/sable/current/qualification` → 读目录 → 未读资格就用错误 JSON 尝试 choose_local → 正确读取 current/qualification，获得 remote → 用错误 JSON 尝试 choose_remote → blocked。此时仍有 1 credit 和 4 个可用步骤。无错误操作真正生效，未触发预算或策略违规；这不是 Cognitive State schema 错误。

成功轨迹也存在接口错误并得到恢复：W02 B 四条件把 current/diagnostic 当 execute，F03 的部分 Summary/CS 把读取当 execute，候选状态 F03 使用了自然语言封包操作名后查目录纠正。ToolUsageCorrectness 因此可以低于 1；单纯合法 finish 又可以使该指标为 1，不能拿它替代 Task Success。

## 成功轨迹说明了什么

- W02：A 直接修复，2 credits；B 先诊断后修复，3 credits。
- F01：A 仅查询既有提交回执，1 credit；B 先提交再查回执，2 credits。
- F02：只执行尚未完成的两个阶段，4 credits。
- F03：A 只读取 B，B 只读取 A，再执行 seal_blue_green，2 credits。

以上分支在四条件中均正确，说明本轮的摘要和自动 CS 都保留了这些续做所需信息。也没有观察到重复执行已完成阶段。不过 W02 可以统一先诊断，F01 可以统一先尝试查询再恢复，并在预算内成功；因此最终成功本身不能证明关键历史不可替代。F03 查询与 W02 再诊断没有 repeat_key，零重复工作记录不能泛化为完全无冗余。后处理重复尝试只覆盖冻结 fixture 中带 repeat_key 的操作。

## 下一轮应检验的问题

1. 冻结本轮数据与结果，在单独执行器校准集验证 choose 操作必须真正执行、execute 必须嵌套 arguments、资源名称要从目录取得；统一改进共同执行协议并建立新 prompt 版本，保留这一轮的失败。
2. 对待审核候选状态逐块检查历史来源，清除抽取器无法获得的具体动作知识；将动作措辞具体程度作为所有压缩条件共享的规则或独立因子。
3. 加入不提供历史的恢复基线，报告成功和达到成功的成本；建设重复查询会消耗预算、无法从重新查询恢复关键历史的任务，同时保持可验证的历史与初始世界一致性。
4. 在独立任务中做无 F、无不确定性等消融与预算梯度，测量信息缺口、证据状态和剩余行动保留是否影响行为；避免把重叠的 G/W/F 标签当作因果归因。随后再增加重复轮次与自然长任务，不训练模型。

这些是后续方案，本轮未据结果调整任务、提示或评分，也未补跑失败组合。
