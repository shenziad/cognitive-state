# 第四轮协议：阶段语义与比较门槛

协议 ID：`cycle4-scoped-lifecycle-v1`。冻结日期：2026-10-03。本轮协议依据已观察的 cycle3 失败制定，属于开发后的新协议，不能解释成对 cycle3 的事前注册。

**本次冻结研究规则、状态编码、规范反例、实验规模和分析标准。执行发布仍关闭：新运行器、完整任务实例及实际消息提示尚待实现和冻结。没有开始真实模型调用。** 机器计划见 [cycle4_plan_20261003.json](cycle4_plan_20261003.json)，协议文件 SHA256 清单见 [冻结清单](freezes/cycle4_protocol_v1.json)。

## 1. 研究目标与条件

先检验带对象范围的阶段表示是否可稳定生成，再比较任务行为与成本，最后检查四次交接中的状态更新。所有结果均为探索性，不作非劣效、等价或总体优越性检验。

四条件：Full Context、任务导向 Summary、CS v0.2、CS v0.3.1。v0.2 保留原状态形状；所有压缩条件获得相同的请求/作业/验收语义说明、可见来源和修复上限。故 v0.2 是旧编码在新共同协议下的对照，不是旧整套系统重放，也不是仅改变单字段的因果消融。

CS v0.3.1 保留 G/W/F，仅为操作记录引入明确对象种类和对应阶段，详见 [生命周期规范](operation_lifecycle_v0.3.1.md)与[编码 Schema](schemas/cognitive_state_v0.3.1.schema.json)。共同语义说明见 [提示附录](../prompts/cycle4/lifecycle_common.txt)。附录须同时进入所有执行条件与三种压缩提示，不按条件额外赠送事实。

## 2. 门槛审查结论

cycle3 的 Full ≥23/24 与“两个条件零严重错误”并列，使一个模型能力失败成为禁止研究模型能力的理由；CS 语义错误也被混入可运行性门槛。对于受控虚拟工作区，这会使进入比较依赖事后表现。新轮采用以下预声明规则，**不追溯解锁旧 gate**。

| 层次 | 具体问题 | 决策 |
|---|---|---|
| 实验完整性 | 隐藏评分/未来事件泄漏；条件信息不一致；评分回放不一致；世界继承错位；源码/输入/提示 hash 漂移；来源权限被程序错误提升 | 阻止启动或停止当前阶段；报告受影响范围及全部已花用量 |
| 服务与记录 | API 中断、用量未知、账本缺失、重复/未归属调用、未完成全部分配组合 | 不发完整性能结论，不扩大到下一阶段；保留部分结果，不挑失败单元补跑 |
| 编码可用性 | 完整预检后任一压缩条件最终有效表示少于 23/24 | 停止扩大；保留失败分母及初次/修复率。所有压缩条件使用同一阈值 |
| 模型行为 | 选错目标、重复工作、过早完成、违规工具尝试、受阻、步数耗尽 | 计入预检/比较成绩；不阻止公平比较，也不触发调提示 |
| 状态语义 | 无依据 job 成功、对象混淆、新增硬要求、重开问题、依赖遗漏、遗漏 pending 作业 | 作为状态结果报告；不以零错误为进入门槛，不挑选“干净状态”执行 |

编码检查仅包括格式、引用形状/存在性、kind-phase 兼容、长度及正常结束；不因候选行动计划差、资源使用不佳或语义标注不符而隐式修复。此变化避免只给 CS 增加一个语义规划检查器。环境按同一真实规则拒绝不合法动作，全部反馈计入成本。

编码 23/24 是预先选定的运行稳定性阈值，并非具有统计保证的可靠性声明。两次重复来自同一模板，不视为独立任务。首次有效率不另设事后阈值。

**Full 的任务成功率不再设门槛；CS 的成功率和语义错误率也不设门槛。** 预检所有条件行为极差仍可通过工程门槛，但必须如实报告，并只运行下述有上限的小比较，不能据此自动扩展规模。

## 3. 阶段、规模与调用上限

| 阶段 | 分配 | 真实请求上限 |
|---|---|---:|
| 离线合规 | 12 个阶段语义规范案例；接口、输入隔离、来源权限、评分、失败门槛与继承测试 | 0 |
| 预检 | 12 实例 × 4 条件 × 2 重复 = 96 组合 | 720 |
| 已知任务回归 | 14 任务 × 4 条件 × 1 次 = 56 组合 | 420 |
| 四次交接 | 2 场景 × 4 条件 × 4 段 × 1 次 = 32 段 | 240 |

最多 1,380 次实际请求。Full 每组合最多 6 次执行调用；压缩条件最多 2 次提取（初次加一次编码修复）及 6 次执行。每次调用和未知用量尝试均占请求上限；客户端不做隐式重试。上限不是预算用满目标；本次没有产生这些调用。

预检六类、每类两个明确版本的场景规范：

1. 提交被接受但作业待完成 / 用户只要求成功提交。
2. 提交超时且是否接受未知 / 幂等查询确认已接受，禁止无依据重提。
3. 正确 job 成功回执 / 其他 job 成功回执，当前 job 仍待完成。
4. job 成功且没有额外验收 / job 成功但用户明确要求独立验证。
5. 取消请求被接受但 job 尚在运行 / 对应 job 已确认 cancelled。
6. 同步效果已完成 / 只有计划且实际尚未执行。

每个场景必须提供可完成的公开恢复路径、准确对象身份、资源额度和契约；Full 可依据公开输入求解。任务标签不得暗示目标答案。离线规范案例包含上述语义边界及错序回执，但不是这 12 个完整执行实例，也不作为模型输入的候选答案。

回归与交接使用 cycle3 已准备、此前已查看的任务作为底稿，哈希纳入协议冻结。新适配只显式标注已有公开回执的对象/阶段，不从隐藏环境补事实；如缺少身份或回执契约，应先补成对公开 fixture 并在调用前冻结、记录差异。这些任务属于开发回归，不是独立泛化测试。

预检使用 seed=20261004 生成并保存一次分配顺序；交接可打乱场景/条件顺序，但同一链 h1→h4 顺序固定。temperature 0 不声称服务完全确定。

## 4. 共同设置与输入边界

- SiliconFlow，`deepseek-ai/DeepSeek-V4-Flash`，base URL `https://api.siliconflow.cn/v1`，Chat Completions `/chat/completions`，temperature 0，thinking=false，max output 4096，timeout 60 秒；凭据只从现有环境配置读取。
- 三个压缩条件均为 6000 UTF-8 bytes，最多一次编码修复；保留初次输出与错误，不自动重写内容、不回退完整历史。Full 不压缩，其所有实际 Tokens 一并记录。
- 下一轮执行消息采用统一 JSON **对象**封装 retained_context、public_interface；不重复把整个 context 编成多层 JSON 字符串。文本 Summary 与结构 CS 本身可保持各自格式；对比真实发送消息的序列化字节与 provider Tokens。
- 当前契约、额度与新事件对所有条件一致。只发当前可见的目录/回执，不能发隐藏 world、评分答案、未读 observation 或未来事件。
- 压缩链只读取上次实际表示及新真实事件；来源定位不会恢复历史。不同条件各自继承真实行动后的世界，不能用参考轨迹重置。
- 只要不是表示/执行格式错误，行为失败后仍按场景公开恢复规则进入下一交接；表示/格式错误导致链不可续做时，后续段标 skipped 并保留分母。预先冻结何时允许重试和恢复，不能只给失败条件补资源。

## 5. 评分与审阅

主指标：Task Success Rate（全部分配组合）；连续任务另报整链全成功比例。辅指标：Final Goal Completion、工具用法正确性、目标/证据决策一致性、重复工作、过早完成、额度违约、无法观察和格式失败。

分别报告 submission 状态、job 状态、业务效果和验收义务是否准确；错误阶段必须给对象和证据。对于 “submission.completed + outcome=accepted / job.accepted” 不记作虚构作业完成。对行为相同但阶段范围模糊的文本，标 ambiguous，不能强制归成错误或正确。

预检审阅全部三类压缩输出（各 24 份最终表示）；提取失败单独列出，不算语义正确。采用统一内容标准：对象/阶段混淆、无依据完成、新增硬要求、遗漏关键 pending、无依据重开、关键依赖遗漏。结构存在性指标单独报告，不因 Summary 不含显式依赖图而直接判它依赖遗漏。后续比较审阅所有最终压缩表示，并为 Full/全部条件复核执行轨迹。

先依据公开输入判状态语义，再揭示轨迹和评分供关联分析。审阅中包含 mixed/ambiguous/未观察分类及证据说明；审阅者能看出表示形状，不能声称条件盲法。助手审阅不是独立人类 gold。语义评分从不回传模型，也不作为仅执行优质状态的筛选。

报告编码修复前/后有效率、语义错误率与行为成功率，不把三者混用。不提供依赖图的内容不会自动当成依赖完备；相反，CS 的空 requires 也不能因为结构合法就自动视作充分。

全部 Tokens 含提取、修复、执行、失败；分列输入、缓存输入、输出与响应延迟。只对双方都有完整观测的配对另报 Token 差，另给包含失败的全分配总成本；不按任务成功筛选配对。未测检索或训练费用不记零。单次试验和已知合成输入不支持长期总体优势或等价声明。

## 6. 冻结、进入与停止

协议冻结后，**进入真实预检之前**还须创建 execution manifest：新运行器/验证器、完整三阶段实例、四条件完整提示、分配顺序、配置、依赖环境、评分代码和离线检查报告的 SHA256。必须引用本协议 manifest 的 hash，且说明与既定规模、设置、语义和门槛一致。不能只依赖“已冻结”文字启动调用。

目前这些执行资产没有完成，所以配置标记 `execution_ready=false`，旧 cycle3 runner 不兼容，不能直接读取运行。这不是等待额外用户许可，而是尚待完成的实现条件；本次工作范围是澄清和冻结协议。

工程检查全通过、预检完整、三压缩条件各至少 23/24 编码有效时，进入回归；回归完整且设施复核通过后，进入四次交接，**没有额外行为成绩门槛**。严重负面结果即时报告但不据此调提示。服务/设施失败停止受影响阶段；恢复需单独版本和完整计划，不选择性补成功样本。编码门槛失败则本轮停止扩大，不自动修订第二版。

所有下一轮输入/提示/配置更改必须在首次调用前完成。改变本文的语义、门槛、任务类别、规模、修复/成本规则，应新建协议版本并保存旧版；改变已调用的执行版本需新实验 ID。cycle3 gate 继续 failed，不用于授权 cycle4。
