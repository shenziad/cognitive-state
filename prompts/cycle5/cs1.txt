Represent the available public history as a compact Cognitive State v0.3.1 using the following exact encoding. The common task semantics below apply equally to this representation and the prose summary controls.
Return exactly one JSON object, with sibling root objects goal, world, frontier, and no other root keys:
{"goal":{"revision":"g1","objective":"text","requirements":[{"id":"r1","text":"observable current requirement","source_refs":["public_source_id"]}],"constraints":[],"preferences":[]},"world":{"claims":[],"operations":[],"resources":[]},"frontier":{"obligations":[],"open_questions":[]}}
Goal requirements, constraints and preferences contain id,text,source_refs. Source IDs must exist in available history or preserved source_authority labels. Use unique short active item IDs. At least one goal requirement is required. Source class labels are supplied separately and convey authority, not source content.
Claims contain id,text,basis,source_refs. basis is observed/reported/inferred/assumed. Optional fields are depends_on (active IDs), standing (active/refuted/superseded/conflicted), valid_when, recheck_when, superseded_by (active ID). Inferred claims require depends_on. Optional metadata should be included only when useful. Preserve the evidence content itself in text.
Operations contain id,kind,entity_id,operation,phase,source_refs; optional target must be an OBJECT, and optional handle must be a string.
For kind=submission, phase is planned/issued/completed/unknown and outcome is required. A completed submission has outcome accepted or rejected; other phases have outcome unknown. An accepted submission additionally requires job_ref pointing to an active kind=job item; nonaccepted submissions omit job_ref.
For kind=job, phase is accepted/running/succeeded/failed/cancelled/unknown; omit outcome and job_ref.
For kind=sync_operation, phase is planned/issued/succeeded/failed/cancelled/unknown; omit outcome and job_ref.
Resources contain id,kind,remaining,scope,source_refs; remaining is nonnegative. Resource source handles may reference the common runtime allowance record.
Obligations contain id,text,requirement_ref (a current goal requirement ID); optional depends_on references active IDs.
Open questions contain id,text,blocks (obligation IDs),decision_relevance; optional depends_on references active IDs. Empty open_questions is allowed.
An OPTIONAL candidate_action belongs INSIDE frontier, never at root or in world. It contains tool (execute/observe), arguments ({"operation":"exact catalog name"} or {"resource":"exact catalog name"}), requires (active IDs), obligation_ref, goal_revision; optional known_cost is nonnegative. The action is merely a suggestion, not an observation. Omit it if no supported feasible action is appropriate.
Do not add any other fields or placeholders. Keep references valid within the actual source/item set. Do not copy the entire public catalog. Use the available public inputs, not a hidden evaluator or future events.
Return the complete JSON only, with no Markdown. Its compact UTF-8 serialized size must stay within representation_budget using budget_counter. Do not return the budget fields. Omit optional metadata before omitting necessary task information.
