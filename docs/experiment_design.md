# 实验设计：从 v0.2 结果到 v0.3 机制检验

2026-10-03：用户已授权恢复实验，v0.3 独立最小实现及两次预检完成。修订版 CS 24/24、Full 23/24，但零严重错误及状态语义门槛未通过，四条件比较和连续交接未启动，见[第三轮报告](../results/analysis/research_cycle3_20261003/analysis.md)。下文为研究设计，不能视为已取得结果；旧两轮仍按原协议解释。

## 共同比较条件

主要比较 Full Context、竞争性的任务导向普通 Summary、自动 Cognitive State。三者拥有相同当前公开事件、工具契约与资源权限；压缩条件只使用实际保留表示及新材料，不能免费恢复旧历史。

Summary 可以保留目标、证据、不确定性、实际进度与下一步信息，也可接受同样的一致性检查原则。限制为普通摘要格式不应成为故意削弱基线的理由。任何修复/恢复机会按共同请求和成本预算设置；报告真实消耗，不假定两条件成本自动相同。

No History 是恢复诊断条件；有来源的人工状态仅作可行性诊断，需标明未人审或人审状态。两者均不替代自动提取主比较。

## 分阶段计划与进入条件

| 阶段 | 要解决的问题 | 进入下一阶段前的条件 |
|---|---|---|
| A：公共接口与设计审阅 | 回执是否足以判断效果和完成？状态来源和更新规则是否自洽？ | 公开工具契约、示例、任务权限与资源范围明确；典型正反例通过离线复核 |
| B：编码与提取可靠性 | JSON/长度错误、无依据要求与重复确认能否减少？ | 冻结有效率阈值、语义错误阈值及样本量；自动表示达到门槛；失败全计入 |
| C：内容与机制比较 | 来源、执行阶段、Frontier、候选计划各自有何作用？ | 有足够有效状态；检查跨字段语义残留；冻结逐项改动及评分 |
| D：连续状态更新 | 目标变更、诊断推翻、异步操作后是否保持连续性？ | 前述门槛通过；真实世界继承；分别评价多轮行为和提取存活率 |

各阶段门槛目前未赋数值；这些值需随样本量和可接受误差一起在调用前冻结。该文档不构成已经预注册的新实验配置，也不自动恢复实验。

## 机制隔离

先修订所有条件共享的工具语义及实际回执，冻结新 fixture 版本。不得只给 CS 更清晰的完成信号，也不能用旧接口结果和新接口结果直接宣称表示提升。

在同一新接口下比较：原提取策略、加入证据/有效性规则、加入操作阶段、加入 Frontier 关闭规则。先做单项对照，再根据独立结果决定组合；相同样本内的组合不当成新增独立任务。

单独比较“有候选行动”与“没有候选行动但保留同样义务和证据”。删除字段后若其他字段仍隐含该信息，不能解释为机制无用。语义消融须跨字段处理、修复悬空引用，并复核没有删除不相关信息或意外加入答案。行动计划修复与信息删除是不同干预。

更新机制比较时，两组获得相同旧表示及新材料；不能让重建组读取全历史而不计入恢复权限和成本。可另设完整历史重建作为明确的额外条件。

## 格式与语义分层评价

同时保存两个结果视图：

1. 端到端：全部分配样本，格式失败、恢复失败、skipped 链均保留在分母及实际花费中。
2. 机制诊断：说明哪些样本真正进入执行，逐类检查内容错误与行为；有效子集有选择偏差，不能作为无条件优越性的证明。

不得将 JSON 失败解释为语义容量不足，也不能将少量人工合法状态当成自动生成成功。严格不修复与有界修复可以分别设条件；保留全部原响应，修复不得读取额外历史或答案。

## 指标

| 指标 | 解释 |
|---|---|
| Task Success / Final Goal Completion | 使用事先固定的独立任务标准；允许不同有效路径 |
| Tool Usage Correctness / Decision Consistency | 分开看格式、前提、约束与实际效果；不以语法合法代替任务完成 |
| 表示有效率 | JSON、结构、长度分别统计；注明提取尝试和恢复次数 |
| 无依据要求/问题重开 | 新增验收要求或确认需求是否有公开来源与失效触发；允许契约要求的独立验证 |
| 操作阶段与目标更新正确性 | 是否把计划当完成、丢失在途 handle、沿用被替换要求 |
| 连续链成功 / 存活率 | 完整链是否成功；单独报告首次提取失败、后续更新失败与实际执行段数 |
| 成本 | 所有提取、更新、校验调用、恢复和执行的 provider input/output、cached input、请求数与延迟 |
| 表示规模 | 编码字节和实际 Token 分开报告；运行时输入与研究归档分开计量 |

来源/问题重开等语义评价需要公开 rubric 与研究者抽查；助手自审不是独立人审。若使用 LLM judge，其成本、盲评协议和误差复核必须记录。

## 预算、数据与不确定性

字节上限用于工程编码约束；Token 预算用于比较实际模型输入。无法精确控制 provider Token 时报告观测值与匹配范围，不能把相同字节数称为相同 Token 预算。

优先形成任务表现—总资源消耗的可行区域，寻找满足预设性能门槛的低成本点。总 Token 下降不能直接换算金额：缓存输入、输出价格与延迟需分别测量；无价格/账单依据时金额为未测量。

任务长度、证据位置、更新次数、变化类型和恢复成本应尽量独立变化；保留未用于调提示的测试集。正式比较需确定重复数、任务/链级统计单位和不确定性估计；同一链四段不能当四条独立链。temperature 0 不能代替重复实验。

第一阶段继续使用 API-based LLM，不训练模型。所有新运行使用新 config/dataset/prompt/state schema 版本、冻结输入和 JSON 结果；旧成绩不覆盖。来源审计归档默认不可被执行器检索；若可检索，则作为额外访问条件计费。
